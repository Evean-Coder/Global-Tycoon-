# 第二轮平衡检验 Spec

状态：用户已批准proposal.md并明确先做测试；四份执行文档按既有自行审批授权自审后执行。范围A–C，不启动未登记的D实验或替代真人试玩。

## 目标

补齐已有466个结果的审计与统计；验证阶段预算可靠性；在有限预算内取得座位和两人路线初筛证据，交付实际缺口与后续改进依据。

## 功能需求

- F1：独立增量预算与证据目录，旧累计预算、旧配置、结果和历史报告不覆盖；规则、策略和随机语义不改。
- F2：稳定选取各人数自然/截断六代表，重新决策并核对全部流水、随机计数和终态；不存在的异常类别明确为空。
- F3：已有结果执行50000次整组重采样，保留原9/24/36比较族、门槛和证据不足结论；代表逐笔账务证据单列。
- F4：阶段预算自动切换；A最多60分钟（审计45/分析15），B最多20分钟，C最多120分钟（采样90/审计分析30）。上限边界不可创建假胜者。
- F5：B每人数4局校准，共12局，来源独立，不计正式胜率；测量局长与实际运行开销，验证异常恢复和阶段预算。
- F6：C每人数20个独立中性种子共60局；六两人配对每组20种子×2座位共240局。先核对B吞吐，不能完成300计划时在开始前登记缩减的完整组方案；不按胜者删改计划。
- F7：真实引擎合法开局与行动，只有最后存活者算自然胜利，500完整轮/20000动作上限为截断，预算中断为待恢复；首错停止。
- F8：输出覆盖、胜率分母、区间、经济、机遇与局长；区分容许范围内/明确偏离/值得复核/证据不足，旧门槛不降低。

## 约束与边界

原生Node20工具，无生产依赖。全局验证输出沿用2GiB上限，不删除既有证据。冻结原30源码指纹；新增控制器与分析入口置于独立位置并单独登记摘要。旧批审计/分析使用原模块，所有新增来源区分。真实3000服务与真人房间不用于自动测试。不修改生产规则或推进玩法数值调整；真人阶段不能自动补写。
