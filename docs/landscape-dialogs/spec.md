# 手机横屏弹窗整体整改 Spec

2026-10-13。依据用户五张手机截图及修复要求，沿用文档自行审查与已批准整改授权，先文档后实施。本轮继续暂停推送。

## 背景与目标
手机浏览器地址栏占据高度后，股票、机遇、自救和经营窗口将大部分可用高度分给说明和按钮，正文被挤为窄缝。目标是让横屏下关键内容、真实金额及操作可读可触达。

## 功能需求
- F1：手机横屏弹窗使用可用视口，紧凑标题与固定关键操作，内容不被其他段落压缩、覆盖或横向溢出；系统字体放大仍可滚动完成操作。
- F2：股票窗口左侧城市列表，右侧资金/额度/草稿摘要与交易操作。城市姓名、价格、归属、买卖数量及原因保留；详细说明可滚动查看。股票选择、滚动、详情返回与回执流程保留。
- F3：初始机遇横屏三卡并列，标题和选择按钮保持可见，完整描述可在卡内阅读；后续路线窗口也采用紧凑头尾及可滚动内容，替换/保留流程不变。
- F4：经营主窗口与子城市窗口按横屏压缩无意义间距，底部左右按钮顺序和各自含义保留；自救、募资、银行、资产、购买/建设/飞行/拍卖/转让/详情/规则/结算正文按自然高度滚动，操作不被压成细缝。
- F5：手机仅横屏、旋转提示优先级和原经营弹窗优先级保持；电脑、平板及旧对局正常可用，资源缓存更新。

## 约束与不做
不修改服务端规则、价格、动作、期限或游戏版本，不自动刷新在玩对局。不引入框架，不删除必要信息或用微小字体凑布局。以有限受控场景和必要浏览器回归验证，不大量模拟整局；不推送。

## 验收标准
- AC1/F1：844×280、568×320、932×430与手机桌面网页模拟宽980×400下无窗口超出视口、整页横向滚动，关键按钮至少44px。
- AC2/F2：股票城市区域占至少窗口内容高度的60%，第一座可交易城市加减及数量可触达；操作栏和城市正文不重叠。更新/买卖/返回保留草稿与位置、初始新窗口置顶。
- AC3/F3：初始三卡标题和选择按钮均在视口内，完整长描述可滚动，提交和换组仍可完成；后续路线可选、替换/跳过。
- AC4/F4：长自救、银行、资产及经营城市内容不收缩；列表任意末项、支付/确认/返回可滚动触达。购买/建设/飞行/拍卖/转让/规则/结算也可完成原操作。
- AC5/F5：手机最高旋转阻挡、经营底部左右按钮、键盘及200%缩放、PC/平板布局和缓存回归通过；记录实际证据，仅本地交付。
