# 自救身份、原因与无限时 Spec

## 背景与目标

自救缺少明显的玩家与付款来源信息，且超时会自动放弃。用户要求明确谁因何欠款，需要自行筹足资金或主动放弃才结束自救。

## 功能需求

- F1：自救窗口顶部常显自救玩家、付款原因、当前缺口；已知城市/机场、收款人和原付款额一起显示。旁观玩家在玩家信息处看到谁因何自救。缺历史资料不推测。
- F2：普通与快速模式取消独立自救期限，不能因为等待、部分筹资或重连而自动破产。没有可变现资产也等待玩家决定。
- F3：筹资足额自动按原流程继续；主动放弃才按原破产流程处理。出售、拍卖子流程完成后恢复无时限自救，身份和欠款来源保持。
- F4：AI仍按原策略筹资或选择放弃；其他决定的期限、掉线暂停与快速整局30分钟封盘保持。封盘按原净资产结算，不因自救超时破产。

## 非功能需求与边界

沿用真实状态和原资金/产权/重复请求规则；不重复扣款，不新增框架、运行时依赖或 Socket 动作。三端关键信息常显，不藏在折叠说明内；缓存同步，不刷新进行中的对局。置业扶持预算讨论另存草案，本轮不实现。仍禁止推送。

## 验收标准

- AC1 / F1：租金、机场费及其他欠款显示本人、原因与缺口；旁观者可读，特殊字符安全展示。
- AC2 / F2：逻辑时间超过原60/45秒仍不破产，无自救倒计时；部分卖股后同一决定标识不变，缺口更新；掉线/重连仍无期限。
- AC3 / F3：足额筹资继续原流程，主动放弃破产；出售恢复欠款资料及无限时；失败零修改。
- AC4 / F4：AI有限自救回归通过；正常期限恢复，快速总时限仍封盘。
- AC5：有限引擎、Socket/浏览器与缓存验证、lint和差异检查通过，记录未测项目，仅本地保存。
