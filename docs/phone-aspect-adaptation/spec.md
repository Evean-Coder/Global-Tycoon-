# 主流直板手机连续适配 Spec

日期：2026-10-26。用户要求优化主流直板手机的不同屏幕比例。按此前“文档自行判断，最终开发问我一次”的约定完成自审；用户已回复“开始”，按已确认方案开发。

## 背景与目标

上一轮仅消除整页左侧额外留白，不能解决固定区域比例、可见高度变化、低空间滚动恢复及全部弹窗的问题。目标是让同一套布局在主流直板手机及其浏览器内容区域连续变化时可玩、可读、可操作，并明确模拟和真机验证的差别。调研与106组现状扫描见research.md。

## 功能需求

- F1 按实际可用宽高连续适配，覆盖约16:9至21:9及中间比例，另做更长比例压力检查；不按品牌／型号设白名单。普通／快速、人机／真人共用同一布局。
- F2 地址栏展开收起、窗口尺寸、系统边距、键盘出现及全屏变化后重新排布；左侧沿用已批准的整页左对齐，顶部／右侧／底部按实际空间处理。不能重复扣除浏览器已排除的边距，不能把背景铺满误当作控件可点击。
- F3 保持原12列×11行及42格全部位置。正常可用空间优先完整显示棋盘；右栏按剩余宽度调整，不能固定比例把棋盘挤进不必要的滚动模式。明确空间不足原因，保留可到达的全部格子及放大阅读。
- F4 常显序号、短名、类型图标与归属色；两位编号横排完整，不竖排拆开、不与名称或图标重叠。根据格子尺寸安排单行或上下层；点击继续显示真实全名与完整详情，不改变既有简称对应关系。
- F5 保留中央左资讯／右资产台账及棋盘右侧玩家／事件栏；小空间使用内部阅读与原更多入口，不删除信息。底部保持掷骰→主动经营→查看资产→银行→更多；本人状态、决定期限、快速整局期限继续能察觉。
- F6 大厅和房间同时适配手机竖屏／横屏，昵称、房间码、模式、玩家和开始按钮可达；正式进入对局仍只允许横屏，方向提示优先级保持。
- F7 统一适配经营、机遇、换路线、股票／转让、银行／资产、购地／机场／建房／飞行、募资／自救、规则／记录／回顾等窗口。正文不压扁、重要按钮可达；长列表只在指定正文区域滚动，低高度时操作区可独立有界滚动，不能让卡片内部再各自套滚动。
- F8 自动空间回退与用户主动放大分开；地址栏收起或屏幕变大后，自动回退恢复概览，用户主动放大不被广播取消。系统放大／手势缩放不被强制还原。全屏仅提供主动尝试，失败仍可继续；键盘出现时当前输入与提交／返回可达，不误判物理方向。
- F9 尺寸变化不清空股票数量、经营／竞争出价、输入和阅读展开、滚动／焦点，不提交资金动作、不延长期限、不重复弹出决定。地图图片、棋子和真实落点保持对齐，重连继续沿用服务端状态。
- F10 主要行动及弹窗关键操作至少44个逻辑像素高；正常正文至少12px，侧栏摘要至少10px，地块短名至少8px；极小地块明确可放大阅读，不宣称每格都是44px触控目标。保留键盘访问、减少动画与原系统缩放能力。
- F11 更多中提供只读“屏幕适配”说明：当前可用空间、默认／放大状态及空间不足原因；详细诊断可主动复制，用于用户反馈。只包含布局信息，不带房间凭据、昵称、其他玩家私有信息，不自动上传。
- F12 同步本地资源和缓存版本；升级不强刷进行中的对局。发布分别记录本地检查、浏览器内核检查、线上资源与实体机观察，不能将UA模拟写成真机通过。

## 正常完整棋盘与回退边界

正常目标：扣除浏览器工具栏和顶部／右侧／底部占用后的可见区域宽至少568px、高至少260px，系统默认缩放下应优先完整显示42格。区域足够时也应自动利用更小宽度而非生硬按此阈值拒绝。

更矮／更窄、系统大字或键盘占用时，不能同时保证所有信息大字和全图。本轮要求不裁切关键操作，明确提示并允许滚动／放大／主动全屏；空间恢复后自动回概览。不得以关闭缩放或隐藏原侧栏实现“适配”。

## 非功能与边界

- N1 复用现有技术栈；不新增运行时框架、服务端事件或游戏规则，不改价格、股息、机遇、AI策略、倒计时和棋子移动速度。
- N2 尺寸事件合并处理，稳定后400ms内得到不越界布局；不因测量写回形成持续振荡，不在每个广播中替换整个棋盘或重建输入。
- N3 采用有限局势的尺寸矩阵和少量真实交互，不能用大批完整游戏代替适配检查。厂商比例、合成内容区域、UA模拟、浏览器内核和实体机证据明确区分。
- N4 不新增权限或自动外传设备资料；诊断主动复制。极旧浏览器不支持接口时使用原尺寸与滚动回退，不静默卡死。
- 不做折叠内屏／分屏产品设计、竖屏对局、全新视觉主题、棋盘重排、云游戏或原生应用。既有PC／平板详细布局保留并回归。
