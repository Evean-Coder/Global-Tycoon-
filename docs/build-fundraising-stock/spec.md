# 建房募资卖股 Spec

日期：2026-10-11。状态：2026-10-11用户统一批准开发；实现与实际验证见 acceptance.md。

## 背景与目标

玩家进入建房募集资金界面只能看到持股，无法卖股补足建房款。本轮让建房现金不足时可选择卖出股数筹资，准确显示预计收入、当前现金与剩余缺口，仍由玩家确认建房。

按用户要求先整理独立的Spec、Plan、Tasks、Checklist，自审完成后请用户确认开发。本项与股票列表稳定性/快速时限调整分别记录，最终可以一起审批和交付。

## 功能需求

- F1 本人落到自有城市进入正常建房决定，仍有建房资格且现金不足时，建房募资界面在可出售持股旁显示卖出数量和操作入口。普通、快速模式均可用。
- F2 卖出数量须明确选择，为1至当前本人持股数的整数；展示按当前有效报价计算的预计现金收入。现金足够、不可交易、未持有或无有效报价时，说明不可卖原因。仅不足现金时可发起该筹资卖股；一笔收入允许超过缺口，之后足额则停止提供筹资卖股。
- F3 实际出售沿用当前自救卖股的变现口径，按真实持股和有效报价一次扣股、增加现金，不购买股票、不发起转让、不扣建房费、不自动建房。
- F4 收到成功状态后立即更新现金、持股、实际建房费用和缺口；仍不足可继续筹资。凑够后显示“资金已足够”，保留返回建房入口，返回后玩家手动确认。查看、卖股、返回不刷新原建房期限或消耗建设优惠。
- F5 失败、报价变化、重复点击、迟到回执、重连及超时不能重复出售或修改其他决定；不确定成交时核对原结果，不能自动提交第二笔。取消/超时放弃建房保留已成交的股票出售。
- F6 普通银行继续展示只读持股；本轮新增权限限于合法的建房筹资，不能在掷骰、飞行、购地募资等阶段借该入口任意卖股。原欠款自救和起点股票交易规则保持。
- F7 帮助和规则明确“建房现金不足可卖股筹资”，说明股数、预计变现、实际报价与手动确认建房；缺口来自当前状态而非初次打开时的旧现金。

## 非功能需求

- N1 沿用现有原生前端、服务端动作校验、资金整数规则、报价及重复请求机制，不增加框架或运行时依赖。
- N2 服务端验证身份、建房资格、缺口、持股、数量、报价、阶段和整局截止；失败无部分扣股/入账。私有筹资数量不向其他玩家提供草稿。
- N3 三端触控/键盘可选择股数，当前操作与滚动位置保持可用；提示更新不依赖悬停或颜色。报价变化需要玩家重新确认。
- N4 使用有限固定引擎、Socket及浏览器场景验证，不跑大量完整对局，未验证结果不标通过。

## 本轮边界

不增加股票买入或转让入口、不扩展购地/机场募资卖股、不新增建房阶段、不增加倒计时；不改变建房价格、优惠次数、抵押规则、经营次数、股价或分红规则，不自动出售或自动建房。已卖出的股份不会因放弃建房而回滚。
