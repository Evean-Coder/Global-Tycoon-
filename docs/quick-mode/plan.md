# 半小时快速模式 Plan

版本：v1.0。编写：2026-10-09；审批登记：2026-10-10。状态：用户回复“继续”批准技术设计；依据已批准的 [spec](spec.md)，尚未编码。

## 1. 架构划分

### A1 房间配置与开局

房间保存服务端确认的模式，默认普通。房主通过专用房间配置事件选择，所有成员收到房间状态。正式开局时校验房主、人数、连接、页面能力和一致的模式配置，建立本局版本及计时。

模式配置不复用对局动作，不产生对局决定身份。原创建、加入、重连、开始及请求确认行为保留。重新开局复用房间当前选择，经同一开始请求入口处理，清理上一局时钟和记录引用。

### A2 整局时钟

新增独立整局时钟，以服务端单调时间计算30分钟。墙钟仅用于显示、记录开局和结束时间。时钟依赖可注入，单元和联机测试使用可控时间，不等待真实30分钟。

整局时钟不接入个人暂停。负责调度5/10/15/22/25/28/30分钟节点、5/2分钟余时预告和独立到期回调；节点回调延迟或跳过多个时点时，按当前总时间补齐必要标记，30分钟先结束。客户端插值显示，不能触发成交或裁定结束。

### A3 原子封盘与净资产

新增快速结算模块，在候选状态中依次收集取消事项、取消待处理选择、清算已破产残留城市、结清正常待分红、计算净资产与并列排名。调用现有股票清算和派息，不复制经济计算。

服务端检查金额、产权和结果后一次替换正式状态，再写事件、记录和广播。模块不操作Socket、定时器或文件，不调用掷骰、默认动作或完整回合推进。普通结束路径保留。

### A4 决定时钟与动作提交

复用现有决定身份和动作回执。快速一般20秒、自救45秒、初始30秒、后续20秒；对同一决定只缩小余时，不因资料查看或重试延长。总截止在执行前、提交前和定时回调入口检查。

已有成功请求先查回执缓存，终局后仍返回原成功结果。未成功的新请求到期拒绝，不能在最后时刻补触发个人超时默认操作。

### A5 成长流程与生命周期

继续通过已实现的快速时间适配接口推动初始与后续机遇。到时先标记，安全交接再进入，不取消自救或交易来插入选择。

快速自然胜负、30分钟结束、房主解散及无人清理统一调用快速结束入口。结束后清理个人和总时钟；后续记录读取只使用冻结结果。重新开局或旧时钟回调通过局身份隔离。

### A6 视图、记录与三端

房间增加模式选择，对局增加独立总计时，资产卡显示当前净资产及明细，终局显示并列和取消原因。继续使用原HTML/CSS/JS及Socket，不引入依赖。

对外视图仅增加公开时间和资产信息；未提交初始选择、后续候选和随机序列继续私有。记录v2增加有版本标识的快速结果，旧记录不伪造债务或名次。

## 2. 数据约定

金额为安全整数；时长为非负毫秒；个人与总时间使用同一服务端单调时间源。公开墙钟字段不作为接受动作的依据。

### D1 房间及模式版本

| 字段 | 约定 |
|---|---|
| `room.gameMode` | `normal`或`quick`，仅房主在尚未开始时可修改；结束后可用于下一局选择 |
| `state.gameMode` | 正式开局由房间配置写入，游戏中不可修改；沿用路线模块字段 |
| `state.quickRevision` | 快速新局固定`quick-mode-v1`，普通及旧局不补写 |
| `state.quick` | 快速元数据及冻结结果；普通、旧局不存在 |
| `room.quickClock` | 单调总时钟实例，不放入JSON快照 |
| `room.quickTimeProvider` | 复用路线适配的`read(room)`与`close(room)`协议，绑定本局时钟及统一封盘入口 |

`state.quick`包括`durationMs: 1800000`、`startedAt`、`status: running/closed`、已发预告标记，结束后记录`endedAt`、`elapsedMs`、`reason`和`result`。决定是否到期始终查询`room.quickClock`，不累加广播次数，也不复制可暂停的总截止计时器。

新增页面能力`clientQuickRevision: 'quick-mode-v1'`，与原`clientRouteRevision`并存。普通开局沿用原路线能力门槛；快速开局要求所有成员具备快速能力。能力校验只是兼容检查，不替代服务器规则和身份校验。

### D2 总时钟接口

新模块`src/quickClock.js`提供`createQuickClock({now, wallNow, setTimeout, clearTimeout, onAdvance})`，缺省使用现有Node单调时间和系统定时器。实例接口：

| 接口 | 约定 |
|---|---|
| `start(gameId, startedAt)` | 只在合法开局调用，记单调起点，关联本局身份，并安排下一节点 |
| `read()` | 返回`{mode:'quick', gameId, elapsedMs, totalRemainingMs, closed}`；未结束时总余时不小于0 |
| `schedule()` | 安排下一未到节点；回调只通知服务器读取时间并推进，不直接改变经济状态 |
| `stop()` | 取消回调并冻结实际时长，幂等；不能将已过时的总余时恢复为正值 |

节点回调包含局身份，旧局回调不得影响新局。定时器不是截止的唯一保障：每个动作及广播恢复入口也读取当前总时间，处理回调延迟。到期与关闭是不同事实：`elapsedMs>=1800000`即不允许成交，即使结束回调还未执行。

当前适配`routeTime(room)`所需四字段保留；`close(room)`调用`closeQuickGame(room,'time_limit')`。现有受控provider测试可保留，但真实集成测试必须用本模块，不用假的`close`替代经济结算。

### D3 净资产与排名结构

在`src/assets.js`增加`netAssetSummary(state, playerId)`，继续调用`assetSummary`取得资产组成，保留原函数和普通展示语义。

返回`{cash, propertyValue, airportValue, stockValue, retainedPending, grossAssets, mortgagePrincipal, mortgageInterest, netAssets}`。本金按本人实际抵押城市的现有抵押估值累加；利息按这些城市的累计利息累加，不再加未用于当前抵押账务的玩家级旧字段。

进行中的股票值使用当前含待分红报价，`retainedPending`只计城主未发行股份/取整剩余收益，沿用现有总览的防重计逻辑；未发生的H4奖励不预估。终局在真实派息后计算，正常资金池与`retainedPending`归零，股票使用派息后的报价。因此现场净资产可随终局合法奖励变化，客户端不自行猜测最终金额。

冻结`result`结构：

- `reason`：`time_limit`、`normal`、`disband`或`idle_timeout`。
- `elapsedMs`、`endedAt`：本局实际结束时间。
- `ranking`：`{playerId, rank, alive, netAssets, summary}`列表；存活者同额同名次，例如1、1、3。
- `winnerIds`：并列最高存活者全部ID；自然只剩一人时只含该人。
- `cancelled`：公开的阶段、操作类型、相关玩家/城市及原因；不保存未提交候选和本地股票草稿。
- `clearedCityIds`：本次为已成立破产收尾的城市。

兼容的`state.rank`保持排序后的ID数组；并列使用新`ranking[].rank`展示。单独胜者写入原`state.winner`，并列时`winner=null`、`winnerIds`完整，不能把排在数组首位者显示为唯一赢家。出局者按原破产顺序反向排在存活者之后；稳定显示顺序只用于列表，不破坏并列。

### D4 Socket与视图

| 入口或字段 | 约定 |
|---|---|
| 新`setRoomMode` | 输入`{gameMode}`；校验认证连接、房主、房间未运行、枚举；成功广播`roomState`并回执确认模式 |
| `roomState.gameMode` | 所有成员看到服务器选定模式；旧载荷缺失按普通展示 |
| 原`startGame` | 前端发送已确认模式；缺省使用房间配置；载荷与配置不一致拒绝并提示核对，不私自更改房间模式 |
| `gameState.quickTime` | 保留路线已有时间上下文，增加公开局身份；每次状态及重连重新读取 |
| 新`quickTimeUpdate` | 公开时间轻量校正，包含局身份和版本；每5秒一次，避免每秒生成完整游戏快照 |
| `players[].netAssetSummary` | 只在快速适用新局追加；不能包含随机、私有候选或凭据 |
| `gameState.quickResult` | 封盘后输出冻结结果；对局中不存在 |
| `gameRecord.quick` | 记录快速版本、时长、原因、净资产明细、并列、取消及收尾，与冻结结果一致 |

`quickTimeUpdate`不增加状态修订号或决定身份，不重置股票草稿及选择弹窗。旧局时间包和小于当前接收时间进度的迟到包忽略；客户端本地单调插值到0后只显示“等待服务器结算”，不自行判赢家。

模式设置等待/超时也显示反馈；迟到回执不得覆盖后来由`roomState`确认的模式。重新开始按钮改为经过现有开始反馈入口，使用房间已确认模式，避免直接Socket调用绕过反馈。

## 3. 模块接口与依赖

| 模块 | 接口与职责 | 依赖 |
|---|---|---|
| `quickClock` | 上述总时间接口、节点与轻量校正触发 | Node时间/定时器，不导入游戏引擎 |
| `assets` | 新`netAssetSummary`，原总览保持 | 现有整数经济函数 |
| 新`quickMode` | `enabled(state)`、`finalize(state,{reason,elapsedMs,endedAt})`；修改调用方给的候选并返回事件及冻结结果 | 股票派息/清算、资产、路线取消；不导入server |
| `actionClock` | 识别快速20/45/30秒；增加总余时预算收紧能力 | 只识别状态版本和传入预算，不导入总时钟实例 |
| `gameLogic` | 快速安全成长检查；自然结束只产生待收尾意图 | 原机会/路线；不导入快速结算模块，避免与股票/资产循环依赖 |
| `server` | 创建时钟、推进时间、截止门槛、原子提交、记录/广播、房间配置 | 上述模块及现有校验/记录 |
| `gameView`、`record` | 投影公开净资产和结果，旧格式兼容 | 资产和冻结结果，不产生新结算 |
| 原生前端 | 模式、双时钟、资产和并列结果 | 现有Socket和UI函数 |

`actionClock.sync(state,onTimeout,newDecision=false,totalRemainingMs=null)`增加可选第四参数。普通不传预算，原语义不变；快速按阶段选择上限并取总预算较小值。同一决定再同步只缩短当前剩余时间，决定ID保持；暂停状态可以缩小展示/保存余时但不恢复个人定时器，总时钟仍可结束。恢复后重新限制到真实总余时。

## 4. 交互与提交顺序

### I1 开局

1. 房主选择模式→服务端校验→房间广播→成员看见已确认选择。
2. 开始请求校验房间、模式、页面能力；失败不清空原局或启动时钟。
3. 在本地准备新状态、随机牌组、首阶段和计时实例；开局开始点先确定，初始化时间计入总时长。
4. 新局配置与时钟一起安装到room，清理旧时钟/回执/记录引用；正式广播房间、游戏和双计时。

### I2 动作

1. 验证连接身份，先查询已有成功回执。
2. 读取总时间；到期直接结束原正式状态，不执行动作。
3. 推进到时标记，再检查动作信封、个人期限、阶段和资格；原决定被合法新阶段替换时旧动作拒绝。
4. 在状态副本上执行，核对经济/路线不变量。
5. **提交前再次读取总时间**：达到截止则丢弃副本，在原状态上封盘；副本中的扣钱、机遇和随机结果不广播。
6. 尚未到期且合法，则提交一次、增加修订、追加事件、缓存回执、广播。

生产随机源不保存于对外状态；副本未提交时骰袋、资产和候选状态不提交。跨总截止后直接结束，没有后续对局动作消费被丢弃结果。固定随机测试不将“已生成随机数”当作“已成交”。

### I3 时间推进

1. 节点、轻量心跳、状态恢复或动作入口读取同一时间源。
2. 到30分钟先统一结束，不再生成机遇和个人超时默认动作。
3. 尚未到期则在副本上登记初始与后续时点、第28分钟关闭和公开预告。
4. 初始阶段只在安全交接进入；已经准备好且尚未掷骰的合法入口可检查到期阶段，但不能重复执行监狱释放或回合收费。个人后续继续复用`tryOpenRouteChoice`。
5. 提交前再检查总截止；若有阶段变化，按新决定计时；只更新时间包时不重置决定。

保留原`markQuickDue`对累计时点与重复调用的处理。初始入口补充引擎级安全检查，不在server直接重放`prepareTurn`；同步选择的continuation明确恢复原掷骰前状态或原回合交接。

### I4 统一结束

`closeQuickGame(room, reason)`检查是否已有本局冻结结果，再复制正式状态：

1. 从pending和未结束公共阶段收集公开取消事项。
2. 取消未提交路线，清空普通未成交决定；保留存活者的原产权和负现金。
3. 遍历仍由已出局玩家持有的城市，调用既有`clearCityToBank`；不依赖已被清空的破产玩家`cities`数组，不启动新拍卖。
4. 调用既有`settleFinalEconomy`一次；先清算破产残留再派正常城市股息。
5. 计算净资产、并列、出局顺序和赢家，冻结结果，置`over/game_over`并清空待处理流程。
6. 核对不变量后一次提交并追加公开事件；结束时钟、生成唯一记录，再广播结果。

普通卖方拍卖的城市不归银行；无主拍卖仍无主。自然提前结束复用同一顺序：引擎在快速局只标记结束意图，不提前调用普通终局派息；确认仅剩一人时跳过未开启破产拍卖。只有副本提交后才形成自然获胜事实。

所有快速结束入口都走该路径。现有解散事件的普通总资产再排序不能覆盖快速净资产结果；无人清理先生成正确结果和记录，再移除房间。快速结果存在后，`emitGame`不再以默认`normal`重写结束原因。

结算函数失败不替换正式状态、不关闭为半成品，也不宣布结果；总时钟仍判为到期，新动作拒绝。结束重试幂等并记录错误，不把工具异常当玩家正常输赢。

### I5 断线、重连及重开

本项目先保留当前正式离线暂停行为，独立总时钟和轻量通知不受其影响；离线推进交付时只更换个人决定等待策略。

运行中重连先读取本局总时间，已到期先封盘，再发送身份对应视图及记录。终局后查询旧成功回执返回原结果，其他新动作拒绝。清理或重开时取消旧局节点和轻量心跳，回调再次校验gameId，避免30分钟旧回调结束新局。

## 5. 三端与记录设计

- 房间选择采用原生控件，普通/快速说明紧邻；非房主显示已选模式。与既有手机横屏提示同时可见。
- 整局时间在资讯/状态区独立展示，个人时间保留操作区；短横屏纵向重排，不把大块固定计时卡叠到棋盘上。
- `renderLedger`快速改用“当前净资产”，保留现金；详细视图展开资产组成、待结收益及抵押负债。普通继续原资产总览。
- 收到权威终局状态立即结束视觉动画、关闭股票/转让/机遇旧面板，清理草稿，再显示结果；不能让动画队列延迟十几秒仍展示可操作按钮。
- `renderGameOver`快速使用冻结名次、全部赢家、结束原因和实际时长，明确取消/清算事项；普通使用原分支。没有记录消息也可从状态显示结果，下载仍等待真实记录。
- `buildGameRecord`快速使用冻结结束时间和结果；原v1/v2及普通字段保持。新增`quick`受`quickRevision`约束，旧记录不计算假净资产。
- 规则速查分列两模式，解释时限、净资产、债务、除息、同分和机会时点。更新生成规则目录时保留一致性检查。

## 7. 技术决策

| 编号 | 决策 | 理由 |
|---|---|---|
| K1 | 单调总时钟，独立于决定暂停；墙钟只记显示时间 | 断线和系统墙钟变化不能延长游戏 |
| K2 | 独立截止回调加入口前/提交前检查 | 回调晚到或执行跨截止仍不成交 |
| K3 | 全部快速结束走同一原子候选结算 | 清算、股息、名次和记录保持一致 |
| K4 | 净资产复用资产明细再扣本金/利息，标准地产估值保留 | 抵押不能虚增排名，也不暗改批准估值 |
| K5 | 排名显式支持并列，单winner仅保兼容 | 不让数组显示顺序成为隐含胜负规则 |
| K6 | 复用路线时间provider与现有Socket动作信封 | 已批准模块可真实集成，回执语义连续 |
| K7 | 5秒轻量校正＋本地只读插值 | 计时可见，不每秒重算全棋盘或卡片 |
| K8 | 新`setRoomMode`仅管大厅，gameMode由服务端固定 | 全员开局前可核对模式，不靠房主本地选择 |
| K9 | 能力标识、普通兼容、旧局不迁移 | 混用缓存不误开无法操作的新模式 |
| K10 | 静态版本`20261009-quick-mode`，缓存`global-tycoon-v11-quick` | 与实际开发批次一并更新，部署时若日期变化登记实际值 |
| K11 | 可控时钟的规则/Socket检查及有限浏览器场景 | 不等待30分钟回归，不运行大批完整局 |
