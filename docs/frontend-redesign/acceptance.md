## 验证环境与范围

使用 Windows、Node v24.18.0、Edge Chromium 和项目现有 Playwright。本轮没有增加依赖或修改 Node 20 部署约定。布局检查采用 1440×900、1366×768、1024×768、768×1024、430×800、375×800、320×800 视口；资产、银行、股票、规则、错误与结算分别检查 PC、平板、手机边界。

200% 缩放采用 1366×768 屏幕缩放后对应的 683×384 CSS 视口，实际打开并关闭资产与银行弹窗；页面已允许浏览器缩放。实体手机／平板的触控、浏览器原生缩放和系统 DPI 未进行人工验收，因此这些测试不代表实体设备实测。

资产动作场景在测试服务中布置已拥有城市、机场与股票的状态，后续抵押、购买、拆房自救、股票放弃、重连与解散均通过正式 UI、Socket 和规则引擎完成；正式页面中没有加入测试入口。

## 验收发现并修复的问题

- 1366px 地块面积不足：增加外围行列在棋盘中的比例，并加入旧网格尺寸对比。
- 四人同格棋子越界：改为按地块宽高排列的格内布局。
- 四人 PC 侧栏末尾被操作栏遮住：限定侧栏高度，玩家与事件区分别滚动；棋盘容器不再被侧栏拉高。
- 平板竖屏操作文字挤压：操作栏分成信息与按钮两行，调整对应棋盘高度。
- 资产与银行追加文字重建节点：保留原节点和处理函数，实际抵押动作复验通过。
- 弹窗标题获得焦点后反向 Tab 可能离开遮罩：补齐首尾焦点循环并复验。

测试中的帧读取、异步状态等待和 Service Worker 验证方式也已修正，最终结果均为通过。
