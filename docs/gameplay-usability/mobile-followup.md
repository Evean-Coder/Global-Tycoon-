## 核查事实

- 用户提供2652×1200横屏截图：标题、资讯、固定操作栏占据大部分高度，棋盘被覆盖。宽度识别把横屏手机分到了平板布局；旧短屏样式主要处理地块，没有重排整页。
- 线上375px浏览器创建正常，未复现所有手机都无法创建。上线健康接口1039ms、握手882ms、首页1028ms；单次WebSocket建立1394ms/回执224ms，轮询建立1952ms/回执897ms。探针用非六位不存在房间码，没有加入玩家房间。这不是所有手机的网络性能结论。
- 本地同一连接创建两次后属于两个房间，好友加入最新房间，该房间有2人，开始却返回“至少需要2名玩家”。服务端查到第一个房间；旧客户端开始不接收回执，不能展示原因。
- 创建/加入没有请求锁与超时反馈；本地存储写入异常未捕获。处理慢时重复点按、连接中点按及限制存储的浏览器缺少保护。
- 股票转让“返回”打开资产页，购买面板继续隐藏；未提交也没有直接继续/跳过股票入口。旧验收验证绕路重新打开，漏掉常用直接返回需求。
- 服务端任一存活玩家离线立即冻结所有人的动作和时钟。该事实及新规则候选另见[离线方案](../reconnect-experience/proposal.md)。
- Render免费实例15分钟无入站流量会休眠，唤醒约1分钟：[官方资料](https://render.com/docs/free)。本轮没有等待冷启动或改变套餐。

## 手机布局

大厅/房间：横屏建议在卡片第一段，连接状态明确显示；输入与动作分组，等待期间按钮显示处理中并防重复。

横屏对局（包括宽884×高330的短屏）：

```text
┌─ 紧凑标题 / 规则入口 ────────────────────────────┐
├─ 当前资讯（可展开/滚动） ────────────────────────┤
│                                                 │
│  棋盘与地图上层资产；在独立内容区上下滚动          │
│  地块名称/归属/房屋/抵押保持，所有42格可到达        │
│  下方玩家和事件仍能滚动查看                       │
│                                                 │
├─ 骰子 / 当前回合 / 时限 | 本轮主操作 / 资产 / 银行 ┤
└─ 操作栏占自己的布局行，不覆盖滚动内容 ────────────┘
```

竖屏：顶部显眼横屏建议，继续允许竖屏创建、加入和游玩；单列内容、正常上下滚动，文字不隐藏、不进一步缩小。不强制旋转、不增加开始前确认。

股票窗口：从股票市场进入转让，返回时恢复同一窗口与草稿；市场增加只读“查看资产”，从资产页进入转让则回资产页。当前股票决定提供明显继续入口，即使关闭资料页也可重新操作；查看/返回不成交、不跳过、不延长时限。

## 技术设计增补

- 手机短横屏采用受高度约束的三段页面布局，内容区域独立纵向滚动；普通PC/平板保持既有页面结构。视口与滚动变化只重排棋子，不提交动作。安全区与浏览器动态高度纳入适配。
- 开局请求绑定请求令牌，统一处理连接、处理中、成功、失败和10秒未确认；明确不以新请求身份自动重放创建/开始。创建服务端对同一连接、同名的重复请求返回已创建房间，避免多房间歧义；其他规则不变。
- 存储读写失败不阻断页面；恢复凭据失败明确提示刷新后重新加入的限制。
- 联机尝试优先WebSocket并保留轮询失败回退；只采用当前已安装客户端具备的能力，不新增依赖。
- 转让查看绑定来源与股票窗口，过期返回不打开旧决定；本人仍在股票阶段时提供恢复面板的只读入口。
- 静态版本与缓存一起递增，新入口兼容旧缓存外壳，更新验证包括此前v6。
