2–4 人浏览器实时联机经营桌游。玩家在 42 格环球棋盘上购置城市、建房、经营机场与投资股票，通过环球资讯和经营机遇调整经营路线，最后一位存活玩家获胜。

## 快速开始

需要 Node.js 20 或以上及 npm；项目 CI 使用 Node 20，最近一次完整验证使用 Node v20.20.2。

```bash
npm ci
npm start
```

打开 <http://localhost:3000>，填写昵称创建房间，将六位房间码发给朋友。2–4 人加入后房主可开始，无需另行“准备”。新对局先进行经营机遇三选一，再进入掷骰流程。

- 默认监听 `0.0.0.0:3000`；用环境变量 `PORT` 修改端口。
- 局域网手机/平板访问 `http://电脑局域网IPv4:3000`，设备需能互相访问；Windows 可用 `ipconfig` 查看地址，并按需要放行该端口。
- 健康检查：`GET /healthz` 返回 `ok`。
- 直接打开 `public/index.html` 无法进行联机；[离线设计 demo](docs/frontend-redesign/demo.html) 仅供视觉预览，不连接正式对局。

## 部署、缓存与数据

- 安装锁文件依赖并运行 `npm start`；反向代理需支持 Socket.IO 的连接和升级。公网部署配置 HTTPS 与可访问端口，环境变量 `PORT` 由运行平台提供或自行设置。
- 房间与正在进行的对局保存在进程内存。服务重启会丢失它们；浏览器重连令牌无法恢复已经丢失的服务状态。
- 终局记录尝试写入项目 `records/`。正常胜负、房主解散及离线清理结束均走终局记录路径；写入失败会记录错误。生产环境需有可写、持久的目录，否则不能承诺记录跨重启保存。
- 结算页面可下载已收到的 JSON、查看事件回放。清理全员离线房间前会生成记录；没有数据库历史大厅或账户系统。
- PWA 缓存名当前为 `global-tycoon-v4-economy`，静态资源版本为 `20261001-economy`。更新客户端需同步 HTML 资源版本与 Service Worker 缓存清单，避免新旧脚本混用。
- HTTPS/localhost 下可缓存页面外壳和图片；离线缓存不提供离线联机对局。
- 清理验证产物前先保留清单、检查点和必要证据；不要将实际记录、身份令牌、整个 `artifacts/` 或用户 ZIP 文件混入代码提交。
