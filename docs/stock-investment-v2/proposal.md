# 股票投资与联合开发：首版玩法草案

日期：2026-10-15。状态：供用户评审，未批准开发、未实现、未发布。

> 本文现为早期讨论留档。用户同意继续细化后，最新四份独立开发文档及255项有限算术结果已汇总在[progress.md](progress.md)。新Spec中的定价、银行退出及估值规则优先；本轮联合开发暂缓，不能照本文旧项目参数实施。

最新设计复核见[改进方向分析](design-review.md)：10股及银行40%使旧定价的房级收益差距扩大，买价和银行退出价需共同重算；建议优先完善股票交易与信息，再评估联合开发。下文未确认的价格、退出费用及联合项目参数保留作候选，不能当作已平衡或可直接实施的最终规则。

最新确认：用户将银行追加分红比例上调为40%，租金承担20%保持不变，合计按同笔经营租金的60%分配给实际持股份额。该比例已确认；不代表本草案其他数值、联合开发或正式开发已获批准。此前“租金承担40%”、银行追加10%及20%均被本次租金20%＋银行40%替代。

后续确认：用户同意减少股数，按紧邻建议将每城20股改为10股；拒绝新增默认持股减租。本稿同步将持有上限、买入额度及合作门槛按原比例缩减为候选，避免6股门槛大于4股持有上限。每股价格不因拆份变化自动翻倍，12%地价仍为待验证候选。现行H6是独立机遇，正式代码保持原样；其是否保留或重做随机遇方案评审，不能将本次对默认减租的否定擅自当作删除现有H6的开发批准。

本稿回应“多买股票没有明确玩法、股票总是优先变卖”的反馈。它修订 management-stock-v5 中的证券经营设计；该目录原来的开发审批请求已不再适用于本稿。订单竞标仍是此前独立候选，不能当作已上线玩法。本稿先评审玩法方向，后续按用户授权自审独立 Spec、Plan、Tasks、Checklist，正式开发前再请用户确认一次。

## 一、核心取舍

推荐：普通股票交易成为资金管理工具；主动经营中的“主动买股”替换为“联合开发”。持股既取得租金收益，也能在达到门槛后发起有风险的合作建设。

备选：仅提高分红并缩短到账等待，改动小，但仍然缺少持股后的决策。另一备选是彻底用行程规划替代股票路线，可增加移动策略，但股票投资自身仍需另行解决。

本稿选择推荐方向，不新增通用的“持股越多、全局加成越高”奖励，也不赋予股东强制建房、夺产权或干预城主回合的权力。

## 二、普通股票：收益更直观

### F1 股票份额及买卖

- 每城10股。城主本城最多2股、每名外部股东本城最多4股，保持原候选20%/40%持股上限比例；上限属于联动候选，尚未独立确认。
- 城市被购买后才有股票。买股取得收益权，产权和建房决定权仍属于城主。
- 初始每股候选价为地价12%，取代现行20%。这是待验证数字。
- 起点窗口候选额度按比例缩为累计4股、最多3城、单城2股；卖出不恢复同一窗口买入额度。
- 正常掷骰前可打开统一股票窗口：每本人回合额外累计买入最多2股、限一城；卖出可选择具体股数。该买卖不消耗主动经营机会，不延长原决定期限，不是另一套库存或报价。起点额度与该回合额度分别显示，禁止通过关闭重开、转让或重连重置。交易额度仍需随10股方案验证，不能将减股数视作额度同步获批。
- 市场买入无手续费；市场卖出按总报价收2%手续费，按现有整数规则取整。玩家协商转让也按转出股份的系统报价收出让方2%手续费，避免零协商价规避费用；手续费由出让方支付，现金不足不成交。接收方支付双方约定价。所有股份路径均守持有上限。
- 普通市场买股款沿原路径结算，不直接交给城主。后述联合开发才把双方现金实际投入建设。

### F2 真实租金即时分红

- 城市每次确认的经营租金收入中，20%按10股分红；银行再以同一笔经营租金为基数，追加40%按10股发放。每股分别对应租金2%和银行奖励4%，合计6%（整数取整除外）；这不是在租金股息金额上再乘40%。没有真实租金就没有这两笔收入。
- 两部分按当时持股即时入账，不等待城主经过起点。租金池、银行奖励池分别沿现有整数规则计算收入20%和40%，再分别除10并对每股向下取整，两笔分别记账；不得先将已取整的租金每股股息乘2代替银行独立计算，以免小额边界产生不同口径。未发行份额对应的租金及零头归城主，其余80%也归城主；银行不为未发行份额或零头付款，也不将其转给城主。
- 城主本人合法持有的最多2股同样获得银行追加奖励。没有持股就没有这项奖励；银行本次实际支出等于银行每股奖励乘存活股东实际持股合计，最多为按整数规则计算的经营租金40%奖励池。城主因普通持股承担的总池比例保持当前20%，不含另行自愿同意的联合开发项目回款。相同持股比例下分走的租金不变；相同股数因占比提高而分走更多，不能描述为对城主现金完全没有影响。
- 自己踩自己的城市不造租金；抵押城市不造基础分红；房租优惠、银行补足沿原资金来源处理，不重复向租客扣钱。
- 不新增按持股数自动减租的默认规则；2股减10%、4股减20%的讨论候选已否决。持股本身仍是收益权，分红回流不等于另收一份租金减免。现行独立H6机遇的后续处置留在机遇重设计范围，当前游戏不变。
- 股东本人付租时，付款和自己的租金股息、银行追加奖励一起计算净现金，再判断是否自救。银行奖励不进入城市租金、报价收入历史或待分红池，不再次触发追加奖励。
- 删除现行“主动买股后额外30%、最高1500、本人经过起点过期”的临时奖励。
- 稳健股息H4原50%额外奖励、本人圈最高3000保留，只按租金承担的实际基础股息计算，不对新增银行追加奖励再叠奖；分散投资H5、股东礼遇H6等现有数值先保持。H4额外款不来自城主，也不计入联合开发回款。本稿先沿用该计算口径，后续有限验证需检查整体补贴叠加。

### F3 报价及退出风险

- 报价仍依据房级、近3完整轮租金及抵押状态；每完整轮最多变动前价10%，保持初始经营价50%–200%边界。
- 房级对估值的影响候选为每级初始价5%，取代现行15%。新报价不再含待派股息。
- 普通卖出不是固定打折回购，但有2%手续费及报价波动风险。
- 城市归银行清算时，持股仍按经营价50%结算并注销；正常产权转让保持股票，按原身份变化处理方式将新城主超2股部分卖出。新局使用10股，旧20股对局不迁移或强制并股。
- 自动处理超额持股与银行清算不收新增自愿交易手续费，避免规则导致的强制操作另收罚费。

## 三、主动经营第三路线：联合开发

### F4 谁能发起

- 玩家持有另一名玩家某城至少3股，且双方存活、城市非抵押，才可在正常掷骰前发起一次合作建房提案。
- 3股为随缩股调整的候选门槛，保持原30%门槛，不额外要求“唯一最大股东”：并列不会导致操作资格突然全部消失。10股总量及单人4股上限限制名额；联合开发整体仍未批准。
- 三条主动经营候选为：远程施工、订单竞标、联合开发。普通买卖股票不再伪装成一条经营路线。
- 每人最多一个待回复提案或未结清开发项目；每城同样最多一个。有效提案提交占用发起者本回合经营机会，拒绝、过期不退机会，但不扣项目款；提交前明确提示这一代价。
- 每人每圈最多发起一次，正常交易和持股本身不受这个项目次数限制。

### F5 城主如何决定

- 提案进入城主收件区，其他玩家正常进行；不插入全员等待或强制确认阶段。
- 在提交后的下一个完整轮结束前，城主可在本人正常掷骰前选择接受或拒绝。拒绝/过期不扣双方资金。
- 接受并成功建设消耗城主本回合经营机会，且沿用该城主远程施工的费用、冷却和不能连续建设同一城限制；因此合作不会绕开远程施工。
- 发起时显示目标房级、双方各需承担金额和项目回款上限。接受时重新验证双方现金、股数、房级、产权、抵押及施工资格。金额或目标已变化则提案失效，不能静默改价扣钱。
- 发起者已确认且仍有效的原提案可由城主接受后一次完成双方扣款、建房和项目建立，不额外要求发起者停下当前流程回复。不允许发起者正处于自救、交易资金确认或其他受保护资金决定时被扣款；此时本次接受不成交、不消费城主次数。
- 接受前发起者可撤销，已用经营机会及本圈提案次数不恢复；撤销和接受先成功的一方生效，不能同时发生。

### F6 成本和回款

- 合作建房总施工费沿用远程施工：目标1/2/3/4级为标准建房费150%/200%/300%/350%，原优惠后总施工费仍不低于标准150%。其他冷却、同城限制不改。
- 发起股东承担总费用一半向上取整，城主承担余数；这是共同支付同一施工费，不是额外打折。双方付款后立即升一级房。
- 股东项目回款上限为其实际投入的125%，包含本金；这是最高回款，不是保底收益。
- 原联合开发候选仍为：在普通租金20%股息及银行40%追加奖励之外，再从城主原可得收入中拨最多本次经营租金40%给项目股东，且不超过项目未回款上限。按最新分红来源，城主至少保留租金40%，另加自己的租金持股股息、未发行份额及取整余数，银行给城主持股的奖励另列；不能继续沿用旧稿“至少保留20%”的描述。项目这项额外40%租金回款本身仍待重设计和评审，本次只确认普通股息20%＋银行40%，未批准项目分配方式。
- 达到上限后项目自动结束，租金恢复普通分配。不新增租客费用、不凭空产生租金，不计作第二次城市收入或重复触发股息奖励。
- 成交后股东卖出股票不撤销已经付费取得的项目回款权；因此该权利是独立的风险投资，而不是靠强锁股票制造持有价值。继续持股的价值是普通分红和下一次合作资格。

### F7 项目失败与封盘

- 没人踩中就没有回款，不保证收回本金。抵押、城市产权改变、项目股东出局、城主出局或城市归银行时，终止剩余回款，不退已经支付的施工费。
- 只在存活期间发实际到账回款，不将尚未收到的项目本金或预期利润计入净资产；封盘取消未回款部分。提示快速模式剩余时间不足时的回收风险，不额外延长30分钟。
- 已建房屋遵循原产权和资产估值；普通股权继续按其原规则处理，不因合作项目终止而一起消失。
- 卖股不解除项目存在期间的每人/每城项目上限，不能靠倒手股份重复开项目；不允许项目收益权转让或抵押。

## 四、具体例子（候选数值、无机遇或资讯修正）

城市地价10000、当前0级房；你持3股，初始股票成本为3600。城主当前具备远程施工资格。

| 项目 | 金额 |
|---|---:|
| 升1级标准建房费 | 6000 |
| 远程施工总费用150% | 9000 |
| 你与城主各付 | 4500 |
| 你的项目回款上限（包含本金） | 5625 |
| 升级后一次标准租金 | 6000 |
| 你3股的租金基础股息 | 360 |
| 银行给你3股的追加奖励 | 720 |
| 你3股的普通持股收入合计 | 1080 |
| 前两次收租的每次项目回款 | 2400 |
| 第三次收租的项目回款 | 825 |

若成功发生这三次租金，你累计收到项目款5625，项目投入4500，项目净赚1125；另有三次普通持股收入共3240。3600的买股本金仍对应股票，出售可得金额取决于当时报价及手续费，不能当作凭空赚到。若封盘前只收租一次，则项目只回2400，尚未回收的2100投入会损失；不保证三次租金一定发生。

上述普通持股收入3240由租金股息1080和银行追加2160组成，项目回款5625另列。项目示例保留用于评审旧候选，不表示额外40%回款规则已经确认。

普通0级城只买2股：初始花2400，一次3000标准租金持股收入360（租金120＋银行240）。这是全城20%的股权，与当前正式20股规则持4股的比例相同；正式版该4股初始成本8000、同次租金积累120且等待结算。该例反映候选缩股、降初价、银行追加和即时结算的共同变化，不是只缩股的独立效果，也不是整局收益或席位平衡证据。

若只有上述外部股东持2股、其余8股无人持有，城主从3000租金最终保留2880。另一个同股数比较：6000租金、外部股东4股、其余6股无人持有，则股东租金480＋银行960＝1440，城主保留5520，银行支出960。此前20股草案4股对应20%，而这里4股对应40%，因此不能声称城主在同股数比较中收入不变；本次只上调银行20%至40%，与上一个10股草案比较则不增加城主租金支出。

## 五、三种玩法应有的区别

| 玩法 | 主要决策 | 主要风险 |
|---|---|---|
| 分散投资 | 挑选不同客流和房级的城市，分享即时租金 | 每城份额少，难发起合作；行情和清算风险 |
| 集中投资 | 凑足3股，挑选愿合作且有回收时间的城主 | 占用较多资金、项目会亏损、城主可能拒绝 |
| 买卖调仓 | 在建设、资讯和其他玩家位置变化时改变配置 | 2%退出成本、判断错误，不能靠无成本频繁倒手 |

集中并非必然更强。合作还要股东追加现金、城主同意和真实客流；分散也不是无条件的全局加成。首次版本不增加收购产权、股东投票、恶意拆房、借股卖空或涨跌停交易系统。

## 六、界面

### F8 信息层级

- 股票列表先显示短城名、房级、每股价、本人股数、市场余量、最近一次每股实际分红；详情再展开报价依据、各玩家份额、累计成本/收入及清算风险。
- 本人持股页显示累计买入支出、卖出净收入、租金股息/银行追加/机遇股息分别累计、当前持仓报价价值；“已实现现金收支”与“含持仓估值的总变动”分开，不把未来收益当到账现金。
- 达到3股显示“可提议联合开发”及真实资格原因；不足时显示差几股，不弹强制买股窗口。不显示已否决的默认持股减租权益。
- 联合开发先选符合条件城市，再列施工费、双方出资、股息和项目回款的区别、城主让出的租金、失败条件及剩余局时。
- 提案列表展示待回复、已拒绝、已失效原因；项目列表展示实付、已回、剩余最高可回和终止原因。收租回执分列租客付款、租金股息、银行追加、项目回款、城主收入；城主页面明确银行追加不从自己的租金再次扣除。
- 三端共享数据，广播保留列表位置、展开及草稿；规则帮助定位本主题，关闭不提交任何交易。

## 七、验收目标及待验证风险

- AC1/F1：所有买卖/转让入口共享库存和报价，城主2/外部4/全城10、每回合和起点额度均不被重开或重连绕过；费用正确。旧20股对局按原版本运行。
