# 环球大亨三端前端改版 Plan

> 文档状态（2026-10-02）：三端改版阶段已交付，T1–T21 完成，28 项检查在阶段记录范围内通过。本文保留批准目标及当时缓存/测试/工作区快照；后续经营界面已接入，当前资源为 v4-economy。当前 UI 见 [UI 参考](../环球大亨-前端UI完整信息.md)，最新证据与完成状态见 [项目现状](../项目现状.md)。

> 基于已批准的 `spec.md`。本计划只改变展示与只读详情入口，继续让现有服务端状态和 Socket 动作决定对局结果。

## 架构概览

1. **视觉资源层（F1）：** 用已确认的深海水面、世界地图和暖白桌游卡片建立统一的颜色、字体、阴影与状态样式。图片作为同源静态资源随项目部署；页面有纯色后备背景。大厅、房间、对局、弹窗和 PWA 主题共用同一套颜色。
2. **响应式布局层（F2–F4）：** 保留现有页面与棋盘节点，以 CSS Grid 和媒体查询重排。PC 为棋盘加较窄信息侧栏；平板随方向改为棋盘优先、信息卡换行；手机以一屏宽的完整棋盘总览为首屏核心，信息区可展开或纵向滚动，操作栏保留安全留白。
3. **对局展示层（F2、F4、F5）：** 保留现有状态渲染入口。棋盘继续按服务端给出的 42 格及原顺序绘制，中央世界地图仅为装饰层；本人资产台账成为地图上层的资产卡，完整资产视图承接原城市行与操作；棋子层跟随棋盘尺寸重新定位。
4. **交互与弹窗层（F4–F6）：** 地块成为可聚焦的原生按钮。城市详情沿用原实现，机场与特殊地块增加只读资料；原大厅、房间、股票、银行、规则和结算入口仍调用现有处理函数。弹窗、倒计时、掉线及错误反馈按原时序显示，并补足响应式尺寸、焦点与减少动画支持。

## 核心数据与接口

| 输入或状态 | 来源 | 消费者 | 约束 |
|---|---|---|---|
| `game` / `gameState` | 现有服务端广播 | 棋盘、资产卡、侧栏、操作栏、弹窗 | 唯一对局数据源；不增字段或改变广播顺序 |
| `game.board` 中的地块 ID、类型和位置 | 现有对局状态 | `renderBoard()`、`gridPos()`、只读地块详情 | 保持 42 格和现有顺时针顺序 |
| 本人玩家、城市、机场、股票状态 | 现有对局状态 | `renderLedger()`、`openAssetOverview()` | 金额和资产数按现有展示口径计算，不使用 demo 示例数据 |
| 当前阶段、当前回合、计时与掉线状态 | 现有事件和本地显示状态 | `renderActionBar()`、`renderPending()`、横幅 | 不改变可执行动作和倒计时来源 |
| 视口尺寸、减少动画偏好 | 浏览器 | CSS、棋子定位、动画展示 | 仅影响排版和视觉动画，不改变游戏状态 |

沿用 `renderBoard()`、`renderPieces()`、`renderLedger()`、`renderSide()`、`renderActionBar()`、`renderPending()`、`openCityDetail()` 和 `openAssetOverview()`。增加的只读地块详情入口以地块 ID 查询当前状态：城市调用 `openCityDetail(cityId)`；机场和特殊地块展示名称、类别、归属或现有规则说明，不发送 `action`。地图资产卡的“查看完整资产”入口调用 `openAssetOverview()`。棋盘容器尺寸变化时重新执行 `renderPieces()`，不修改 `game`。

## 模块设计

### 视觉资源与缓存

**职责：** 提供已确认的两张本地图片、统一颜色变量、文字对比度与后备底色；把新静态图片加入现有离线缓存并更新缓存版本。

**对外接口：** CSS 变量与图片 URL；现有静态文件服务和 PWA 缓存清单。

**依赖：** 浏览器加载本项目静态资源。图片加载失败时，后备底色仍保持按钮与文字可读。

### 页面与棋盘布局

**职责：** 为大厅、房间、对局、弹窗提供 PC、平板横竖屏与手机布局。棋盘仍为 12 列 × 11 行外圈，中央装饰层占内部区域；外围地块在 PC 上放大。固定操作栏对应预留足够滚动空间。

**对外接口：** 现有页面节点与样式类；媒体查询控制布局，不改变页面切换调用。

**依赖：** 视觉资源层；对局展示层提供内容。

### 对局展示与只读详情

**职责：** 把现有状态映射到 42 个地块、棋子、地图资产卡、其他玩家和事件列表。`#ledger` 显示本人总资产、现金、城市、机场和持股概览；桌面可在卡内查看现有资产行，手机以精简概览和完整资产入口保持地图可见。城市行原有抵押、出售和详情入口继续可达。

**对外接口：** 沿用现有渲染函数；为机场和特殊地块增加只读详情展示；地块使用原生按钮响应点击、Enter 和 Space。

**依赖：** `gameState` 与现有展示计算函数；完整资产入口沿用 `openAssetOverview()`。不直接增加 Socket 事件。

### 状态提示、弹窗与操作栏

**职责：** 让回合、计时、掉线、错误、股票、银行、规则、资产和结算界面在三端保持可见、可滚动、可操作；维护弹窗焦点和触控尺寸。强制操作弹窗的展示优先级、确认顺序与关闭条件继续沿用现有逻辑。

**对外接口：** 现有按钮 ID、弹窗节点和事件处理函数；对布局高度变化调用原操作栏留白更新。减少动画偏好只跳过或缩短纯视觉动画，仍执行其后的原状态渲染回调。

**依赖：** 现有客户端事件流。

## 模块交互与数据流

1. 大厅创建或加入房间、房间开始、重连与离开仍使用现有入口和 Socket 事件；新样式只改变呈现。
2. 收到 `gameState` 后，保留当前“骰子／棋子动画 → 状态渲染 → 待处理弹窗／事件”的顺序。渲染阶段更新棋盘、棋子、本人资产卡、侧栏与操作栏。
3. 用户点按或键盘激活地块按钮：按地块 ID 查询当前状态 → 城市打开原地产详情，其他类型打开只读详情 → 关闭后返回棋盘焦点；查看详情不提交游戏动作。
4. 用户打开地图资产卡的完整资产入口：调用原资产总览。抵押、出售等已有操作继续走原处理函数与 `action`，其可用条件不变。
5. PC、平板、手机间切换或旋转屏幕：CSS 重排棋盘与信息区，棋盘尺寸变化后重算棋子坐标，并按操作栏实际高度更新底部留白；不重置对局状态。
6. `timerStarted`、房间掉线状态及服务端错误继续走现有消息处理；视觉层只调整显示位置和可读性。

## 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 对局数据 | 继续由现有 `gameState` 驱动，不新增 Socket 字段或事件 | 保持服务端权威与操作结果不变（N1、AC8） |
| 布局 | 现有 DOM 上使用 CSS Grid、媒体查询与必要的尺寸观察 | 不引入框架，三端共用真实渲染逻辑（N2、F2–F4） |
| 地图素材 | 项目同源静态图片加后备底色，更新 PWA 缓存 | 保留已确认的真实质感，避免 demo 中大尺寸 CSS 内嵌图未显示的问题（F1、AC1） |
| 地图资产卡 | 复用 `#ledger` 与原资产总览，按设备压缩展示 | 地图上可见本人资产，同时保留原城市行及资产操作入口（F2、AC5） |
| 地块详情 | 原生按钮；城市沿用原详情，其他地块只读 | 手机总览中的小地块可用键盘访问，不改变动作协议（F4、N1） |
| 动画与缩放 | 允许系统缩放；减少动画时缩短纯视觉动画并保持回调顺序 | 提高可用性且不改变状态时序（N3、AC6） |
| 弹窗 | 保留现有强制操作的开启与结束条件，增强焦点和滚动 | 保持原操作顺序并适配小屏（N1、F5–F6） |
