## 自审发现并已解决的实施空档

| 风险 | 文档修正 |
|---|---|
| 直接把v4改v5会使现有balanced守卫、机遇与旧文案走错分支 | 独立managementEconomyRevision，只新局显式启用，旧单继续旧计划 |
| 只有原机场ownerId，失去后买回可能错误继续订单 | 新机场产权代次，覆盖两个购买出口和两个归还出口；城市沿listingEpoch |
| 竞价现在不付钱，却被普通经营finalAmount分支当成免费/即时支出 | 分列cashRequired/debitNow，报名独立明确分支，开标原子扣费；AI计未来成本 |
| 输入30档价格需token，但不能让客户端凭空生成服务端确认令牌 | 每城只算一次预览，30档仅生成轻量token，仍走原action，无额外报价事件 |
| 原赢家R+4报名时，预览可能重复叠加旧期优势 | 两分支先去旧优势，仅候选分支合成新优势，模拟两个顺序结算 |
| 相同现金附加在H4上限下不能简单翻倍 | 双分支沿实际股息记账，上海2自持/余700为3280与6480累计 |
| 租金先扣导致误自救、或复用促销后发奖导致重复金融事实 | 单笔计划包含附加/减免/股票/银行/次数，一次提交后再判最终现金 |
| 开标期间恰好30分钟，已算候选不能再扣真实资金 | 保留server提交前总期限门，丢弃过期候选并封盘真实状态 |
| 窗口刷新和低高度横屏再挤掉正文 | 稳定键保留草稿/展开/滚动，单正文滚动，四视口覆盖主页和子页 |
| 报名秘密混入公开记录或私有journal被发给玩家 | 公开白名单；未开奖不公开金额/旗舰；完整journal沿现有仅服务端落盘路径 |

## 取舍与证据限度

基础净利1000–2000、竞争15%/3000/两笔/四轮、暗价100–3000均保持用户要求。订单低价标的利润率仍高，现金充裕时常值得接；圈限制与本金尾付只增加取舍，不证明复杂深度或弱者一定翻盘。商业竞争依赖真实到访，只有一个有效报名也可能中标；同价挑战优先不保证轮换。高房级及股东可能受益更多，银行追加仍会增加货币流入。

本轮重新执行 `repair-model.cjs`，15项设计检查通过，含21订单标的、资格/同价反例及当前股息函数的H4顺序案例，0完整对局；不覆盖新引擎生命周期、真实UI、随机公平频率、平均收益或实际胜率。历史较低/较高参数模型与本轮不能混用。正式开发后按54项记录实测结果，未测真机/Render必须保留限制说明。
