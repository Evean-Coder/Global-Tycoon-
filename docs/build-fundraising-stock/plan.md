# 建房募资卖股 Plan

依据：spec.md。状态：2026-10-11用户统一批准开发；实现与实际验证见 acceptance.md。

## 1. 现状与架构

`public/client.js/openBank(true)` 在 `build_decide` 中显示缺口、抵押其他城市及持股明细，持股无卖出控件。`src/actionValidation.js/phaseAllows` 与 `src/gameLogic.js` 的 `rescue_sell_stock` 都只允许 `self_rescue`。`finishRender` 每次有效状态更新调用 `renderPending`，需保留本人建房银行上下文以免卖股后被自动换回普通建房弹窗。

采用有限复用：沿用 `rescue_sell_stock` 动作及原出售结算，在合法现金不足的 `build_decide` 中增加严格筹资资格校验。两处阶段保护同步修订，不新增Socket事件，不复用起点 `stock_trade`，不打开起点买股额度。

## 2. 数据与接口

- 请求沿用 `{type:'rescue_sell_stock',cityId,shares,quoteVersion}` 及原gameId、decisionId、actorRevision、actionId。建房路径必须显式提供正整数shares，不能沿用历史省略数量即全部出售的自救兼容行为。
- `cityId` 为卖出的股票城市，建房目标只从服务器 `pending.cityId` 读取。筹资校验：本人当前决定、正常落点建房、自有未抵押目标、房级小于4、位置正确、buildReady有效、当前有效建房金额且现金不足；卖出城市实际有经营者且未清算，本人持股充足，报价有效。非建房路径继续原自救校验。
- 使用原正常 `economy.quoteBuild` 读取实际费用；现金不足时报价可包含finalAmount但ok为false，必须区分“有有效金额且资金不足”和结构性建房资格失败，不能简单接受任何ok为false报价。校验资格后仍用原建设报价/确认流程，不能提前扣优惠次数。
- 变现使用当前 `stocks[cityId].price × shares`，建房新路径要求单价为正安全整数，收益、持股和个人持股镜像一次修改，整数/安全金额检查沿原服务器提交不变量。现代版本继续校验quoteVersion及清算状态；历史规则仍保留原版本的交易资格，建房新路径也必须验证显式股数与实际持股。
- 出售后的 `finishSelfRescue` 只用于原self_rescue；建房分支不自动结束、不修改pending、房屋或建设额度。日志区分“建房筹资”与“自救”，保留原可回放动作。
- 本地展示上下文 `bankContext={gameId,decisionId}（本人身份和建房目标由原当前决定校验）`，只保存导航/卖股数量，不存第二份现金。筹资缺口每次由本人真实现金和最新建房报价计算。身份、阶段或目标失效立即清理，不能在新的决定恢复旧银行。

## 3. 交互顺序

建房费用不足→原募集资金入口→建立本人建房银行上下文→持股卡选择数量并预览收入→原sendAction携带报价与身份→服务器在副本校验/出售→成功回执及状态同步→保持同筹资面板，局部更新现金、持股和缺口→仍不足继续选择；足够则禁用筹资卖股并提示返回→玩家返回建房、手动提交原respond_build。

报价变化/失败→更新真实信息并保留合法数量供重新确认；未确认成交→复用原请求结果核对，不自动新卖。卖出后不读回执自行给现金加钱。超时/封盘/不同决定→原阶段优先关闭/替换面板并清理上下文，迟到回执不能重开。取消建房沿原pass语义，卖股已成交部分保持。

## 4. 技术决策

1. 新权限只限现金不足的正常落点建房；普通银行不显示可执行出售，购地募资保持当前许可。后者若需要扩展须另立需求。
2. 每次允许卖1至当前实际持股，允许一笔超过缺口；足额后不能再借募资继续卖。服务器执行时重新核对，不信任前端按钮。
3. 股数默认1，不自动选择全部；预计收入明确标为预计，原报价变化和回执规则保留。
4. 筹资更新保留实际滚动容器/稳定持股卡及焦点，复用股票列表稳定性原则，但不耦合其草稿。新增受控建房筹资测试与原股票时限项目可分别验证。
5. 同步前端资源版本和PWA缓存；如果与股票窗口改进一起交付，使用同一最终资源版本，保留各自验收记录。
6. 不同步扩大人机建设募资策略：当前电脑仍沿原建房选择，可调用原自救不受影响；AI策略完整回归有必要时覆盖新保护分支，不擅自增加决策功能。

## 实施核对

新增src/buildFundraising.js共用只读资格保护，校验入口与原引擎共同使用，避免两处资格漂移。建房筹资保留原actionId的请求对象，结果未确认只能查询原请求；重新打开同一决定不能绕过该限制。持股卡按城市维护稳定节点，现金/缺口从最新状态读取。
