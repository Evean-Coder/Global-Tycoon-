# 环球大亨开发参考

> 更新：2026-10-05。以当前规则 v2 源码和已批准增量核对，包含后期远航开支修订。历史审批仍在各阶段文档中，过去版本可通过 Git 历史查阅。当前状态与证据统一见 [项目现状](项目现状.md)，运行见 [readme.md](../readme.md)，玩家规则见 [rules.md](../rules.md)。

### 后期费用增量

新局创建显式传入 `economyRevision: 'travel-expense-v1'`；默认库构造与已有无标识状态继续原规则。`src/travelExpense.js`按`roundFlow.index - 1`计算已完成完整轮：0–79不收费、80–119每个人回合1500、120起3000，升档提前两轮预告。结算发生在正常结束及合法监禁/极地跳过的推进之前，按玩家与`turnId`凭据防重。

现金不足沿用`self_rescue`，内部恢复信息区分正常结束和跳过；抵押、拆房、卖股、出售或破产处理后续接原流程，不重复落点或收费。逐玩家快照只公开费用阶段，隐藏内部凭据/续接。记录单列实际费用与经济修订，旧记录不补算。实现、发布门槛与投资风险见[验收报告](economy-remediation/production-acceptance.md)。

## 1. 技术栈与运行边界

- CommonJS Node.js，运行要求 Node ≥20；CI Node20，最近验证 Node20.20.2。
- Express ^4.19.2、Socket.IO ^4.7.5；前端原生 HTML/CSS/JS，无编译、前端框架、数据库或行情 API。
- `server.js` 启动 HTTP/Socket 服务，`PORT` 默认为3000，监听0.0.0.0；`/healthz` 返回ok。
- 房间、身份映射、当前状态与回执缓存在进程内存；不是多进程共享存储，重启无法恢复进行中的房间。
- 金额采用安全整数；费用百分比四舍五入，每股基础派息向下取整。计算后检查经济不变量。
- 新局默认规则v2；旧规则分支用于状态/记录兼容，产品不提供旧模式选择。

## 3. 状态与视图契约

核心状态包含玩家、棋盘、城市、机场、股票、`turnIndex/phase/pending`，以及以下v2字段：

| 字段/区域 | 含义 |
|---|---|
| `gameId / ruleVersion / revision` | 对局身份、规则版本、提交版本 |
| `turnId / actorRevision` | 回合身份、各行动者版本 |
| `roundFlow` | 完整轮次参与与完成记录；公开为 `completeRounds` |
| `world` | 当前资讯、预告、有效期与资讯已运行完整轮数 |
| `opportunityStage` | 同步选择阶段及各玩家候选/提交；公开部分仅阶段及完成标志 |
| `player.opportunities` | 已选机遇、全局换组剩余次数、个人每圈使用额度 |
| `stockWindow` | 本人窗口ID、报价/上市版本、累计买入数量；公开给本人 |
| `cities[id].buildCosts` | 各级房屋实际支出，用于正确拆房退款 |
| `stocks[id]` | 经营价值、总报价、待分红、三轮租金历史、持股、报价与经营身份版本 |

`gameView.snapshot` 按玩家生成 JSON：公共玩家信息含资产摘要及已生效机遇；本人 `self` 才有候选、提交、额度、股票窗口及费用报价。服务端不把重连令牌、随机袋、未预告资讯、他人的未完成选择发到公共快照或事件记录。

城市基础租金、股票经营价值/待分红/涨跌原因公开可核对。客户端用自己的 `self` 报价展示费用，不自行推导一个可绕过服务端的价格。

资产摘要包括现金、标准地产价值、机场、持股报价与经营者未分配保留收益。当前总资产不直接扣抵押本金及利息；这是实现中的展示估值，不应写成净资产或可用现金。

## 4. Socket入口与动作事务

| 方向 | 事件 | 用途 |
|---|---|---|
| 客户端→服务端 | `createRoom({name})` | 创建六位码房间；同一连接同名重复创建返回已有未开始房间 |
| 客户端→服务端 | `joinRoom({roomCode,name})` | 加入未开始房间 |
| 客户端→服务端 | `reconnect({roomCode,name,token})` | 认证恢复原席位 |
| 客户端→服务端 | `startGame` | 房主开始2–4人新局，首先进入选择；客户端接收回执显示失败原因 |
| 客户端→服务端 | `action` | 带动作字段及v2身份/版本的游戏请求，有回执 |
| 客户端→服务端 | `disbandRoom` | 房主终止并结算 |
| 服务端→客户端 | `roomState / gameState` | 房间名单、本人对局视图 |
| 服务端→客户端 | `timerStarted` | 决定身份、剩余秒、暂停状态 |
| 服务端→客户端 | `reconnectToken` | 本人重连凭据 |
| 服务端→客户端 | `gameRecord / error` | 终局记录、错误反馈 |

服务器身份由认证的当前连接解析，客户端动作中的身份不能指定别人。v2游戏请求至少带：

```javascript
{
  type: '动作类型',
  gameId: '当前对局ID',
  actionId: '本次唯一请求ID',
  decisionId: 123,
  actorRevision: 7
  // 再附该动作所需的城市、决定、订单等字段
}
```

这只是字段说明，示例数值不是可发送的固定参数。费用动作携带 `quoteVersion`；股票动作使用 `windowId`，订单带报价版本及 `listingEpoch`；选择使用 `stageId/candidateVersion`。具体动作枚举与阶段资格以 `actionValidation.js` 为准。

提交顺序：

1. 解析认证连接；检查成功请求缓存，同ID同内容重试返回旧回执，同ID不同内容拒绝。
2. 检查对局、决定、行动者版本和期限；到期先执行服务端默认动作。
3. 存活玩家离线时拒绝对局动作并暂停时钟。
4. 归一化并预检输入、当前行动者、阶段、资产、额度、费用/报价。
5. `structuredClone` 当前状态，在副本上调用引擎；检查现金、股数、房级、费用记录与额度等经济不变量。
6. 拒绝异常、被拒绝或无变化的结果；成功才提交副本、推进版本、追加事件、更新时钟并逐玩家广播。
7. 保存成功回执，每名玩家最近128次；失败不会进入成功缓存或延长同一决定。

拍卖和直接出售的行动者是实际被询问者，不固定等于回合玩家。股票转让先完整核验股份/现金，接受时再次核验后一起提交。获批自救修复从真实pending恢复出售后的欠费/续接信息，忽略伪造客户端上下文。

## 5. 阶段、轮次与时间

常用阶段：`opportunity_choose`、`waiting_roll`、`stock`、`trade_confirm`、`buy`、`buy_airport`、`buy_fundraise`、`build_decide`、`flight`、`auction_bid`、`direct_sale_ask`、`self_rescue`、`jail_turn`、`frozen_turn`、`game_over`。

- 主回合等待掷骰/冰冻/监狱90秒；一般决定60秒；选择全员共享30秒。
- 决定由对局、回合、阶段、行动者和目标识别；同一决定中的操作不能刷新期限。不同城市/响应对象的新决定应给完整时限。
- 同步选择中换组和旁人提交不延时；到期保留已提交项，未提交者选当前第一项。
- 任何存活玩家断线则暂停，全部恢复后继续剩余时间；淘汰玩家离线不阻塞。
- 世界资讯/报价用 `roundFlow` 完整轮次；个人额度在起点刷新；旧 `rounds` 在座位0结束时递增，抵押利息在轮转回座位0时累加。旧收费计数和新的完整轮次不可互换，座位出局仍按既有规则保留。
- 每条资讯三轮，最后一轮预告；选择分别在开局、资讯启动、资讯运行六轮触发。

规则数值、例外和金额示例集中在根目录玩法说明，避免多份文档各维护一套股票表。

## 6. 房间、重连与记录

- 暂存房间由内存Map管理；没有准备按钮，也没有账户/数据库历史大厅。
- 房主在大厅/结束后离线立即转移给在线玩家；进行中房主离线等待10分钟后尝试转移给在线玩家。
- 只有全员离线房间进入闲置回收：未开始10分钟，已开始/结束30分钟；每分钟扫描。存在在线连接时不按这条规则回收。
- 正常终局、房主解散和离线清理在记录前先完成v2已成立收益结算；结算幂等，保留事件，不用额外起点制造收益。
- 记录版本保留v1兼容；v2补充规则/经营账务、基础股息、机遇奖励、保留收益、清算和费用节省。事件记录不是服务端全部隐藏状态转储。
- `server.js` 将终局JSON尝试写入 `records/`，失败记录错误；浏览器收到记录后可下载/回放。目录已被Git忽略，部署必须另行保证可写持久磁盘。
- 内存对局无持久检查点，服务重启不自动恢复；验证工具的检查点仅属于离线工具。
