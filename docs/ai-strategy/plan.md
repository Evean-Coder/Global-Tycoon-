# 人机经营策略升级 Plan

依据：spec.md。状态：技术设计自审及用户开发确认完成，已实施并验收。

## 1. 架构与接口

- `src/botEvaluation.js` 新建纯评估模块：`context(view)`、`forecast(view, steps)`、`evaluate(context, candidate)`、`opportunityValue(context, id)`。只接受快照，计算期不读真实room/state，不修改输入。
- `src/botPolicy.js` 保留 `choose(view,memory)` 和 `fallback(view,memory)`：按当前阶段生成有限合法候选，比较评估值，输出原动作。原RESERVE导出如无生产调用可移除，保留兼容需明确仅为旧基线值。
- `server.js` 在 `runBotDecision` 给策略补充原 `routeTime(room)` 已对真人公开的快速时限；选择和执行前仍走原封盘检查。成功后记忆更新，失败不记录成交事实。
- `src/botScheduler.js` 复用，不改变1秒思考时间、身份隔离或暂停规则。与原动作引擎的依赖单向：评估→公开规则辅助函数，策略→评估，服务器→策略→原动作入口。

覆盖：上下文F1/F7；候选和评估F2–F6；服务器/回退F8。

## 2. 数据约定

`Context`：self、aliveOpponents、board、cities、stocks、selfQuotes、promotions、world、reserve、horizon、forecast、quickRemainingMs。报价中的ok、finalAmount、quoteVersion、listingEpoch优先；评估值不能替代服务端许可。

恢复回合价值判断补充本人activeManagement.usedThisTurn只读布尔值（由原usedTurnId判断，同样随本人快照提供给真人）。监狱/冻结阶段估计恢复经营时采用公开收费规则和本人已知优惠；未知资讯优惠额度不计入，执行后仍以新阶段真实报价为准。抵押利息逐行核对为每完整轮5%本金，估计按有限轮数累积。

`Candidate`：action、kind、cityId/target、cashCost、assetDelta、expectedIncome、riskPenalty、score。金额提交时保持原整数；浮点评估结果仅用于排序。候选没有收益或违反储备则丢弃；不经营是分数0的基线。并列按动作类型、目标ID、股数排序，不按对象插入顺序。

`Memory`：沿用gameId、decisionId、steps、failures、saleAttempts、blockedKey；新增windowId与该窗口已成功卖出的cityIds，决定变化不能清除本窗口事实，窗口/对局变化清除；不存第二份资金和产权。必要的局部募资计划只存目标ID和已尝试动作，不保留旧报价。

## 3. 有限预测与现金储备

### 3.1 移动估计

公开骰子范围1–10，真实实现为洗牌袋，袋内剩余值私有。用每点1/10的有限分布估计，最多8步，转移 `P[t+1][(i+d)%42] += P[t][i]/10`。这是对移动的近似，不宣称真实独立概率。冻结者首步不移动；在狱者首步只考虑1、10各0.1的出狱移动，其余概率原位保留；原位停留不算重复收租，后续按保守普通移动近似并注明局限。机会移动和未来飞行不模拟。

每格估计命中必须用本步“实际移动到达”概率，不能把停留质量当收费落点。前1–2步用于近期风险/航班，完整有限视野用于经营预期。

普通horizon=8。快速总时限完整且剩余>0时：已完成至少3轮，用elapsedMs/completedRounds估计每轮耗时并夹在15–180秒；否则60秒。`horizon=min(8,remainingMs/estimatedRoundMs)`，允许不足1步，用该比例缩减收益；remaining缺失时horizon=1并禁高溢价主动建设。时限为0则不新增投资，交原封盘处理。

### 3.2 储备

本人未来1步十个可能落点，对他人城市使用本人真实租金quote，对本人城市按0支出；机场费沿公开原规则计算。取该集合最大已知支出R。开支E取currentAmount与未来两轮内preview中较高者。`reserve=ceil(6000+0.6*R+2*E)`。不预扣私有未知机会费用，不把负现金视为可投资。

快速剩余不足60秒，储备仍覆盖本人一步支出与回合费用，不因“快结束”盲目花光现金。任何投资/票款/转让须cashAfter>=reserve；自救以现金补足0为目标。

## 4. 统一收益比较

`score = assetDelta + discountedExpectedIncrementalIncome - riskPenalty`，未来收入按每步0.92折现；比较的是相对不做动作的增量，收入与资产估值不能重复计。

- 买城市/扶持/直接购买/拍卖：assetDelta=原城市含房价值-实际支付。2026-10-11逐行核对原transferCity后明确：无主城市按原规则上市，已归属城市易主派发旧基金并保留发行股份；不把旧基金作为购房所得。收入按成交后其他活跃玩家预计到达×资讯后的标准经营租金计算；外部股东的基础收益从城主预期中扣除，本人持股收益合并一次。lapBuys>=4不得买。引擎规则不修改。
- 建房：assetDelta=原名义一级房价值-真实报价；增量租金用原rentFor规则对比建设前后，现有持仓的收益分配按上项。主动建设145%费用和封顶优惠必须采用真实quote；remote报价在现行主动经营版本也受同一回合次数和费用限制，不能假定免费额外建房。
- 促销：实际费用为负资产变化；现有奖励quote与至多两次有效租金完成机会相乘，仅看当前和下一完整轮，超过有效期不计收益；如果已存在本人有效促销，替换损失的未用奖励要扣掉。
- 股票：用公开p0、房级、最近3轮租金及原10%涨跌步长预测经营价，抵押惩罚和价格边界沿原规则；未来新增租金对应股息每股1%，额外机遇按真实上限计。`assetDelta`只计预计经营价变化减手续费，当前待分红已在买价与现有价值中抵消，不另计稳赚。城主买本人股份不会增加原本归自己的基础总租金，仅计真实机遇增量和经营价变化。
- 集中风险：新增持股总值不得超过当前正总资产25%，单城不得超过10%；不因已有持仓超限强制出售，只禁继续增加。现金储备优先于这些比例；无有效总资产就不主动加仓。

资讯按公开当前效果与剩余轮数应用，到期后回归标准；未知未来事件不预测成确定利好。长期外推租金用命中预测与最近实际收入共同约束，不凭一个高历史数值无限抬价。首版所有参数固定在评估模块配置，并在测试前冻结；失败修复可修改错误公式，不能根据输赢临时调参。

## 5. 各阶段行为

### 5.1 待掷骰与落点

待掷骰先处理合法扶持选择；扶持候选分别比较，成功后用新快照重新评估正常经营。主动候选包含报价里全部可用建房、促销、1–2股股票，最多选择一项原许可内经营，不叠加独立remote动作。steps>=6直接掷骰。落点建房/买地/机场使用同一储备与增量评估。

机场资产价值15000；未来收入使用原机场收费与公开数量，并考虑H9已满足邻城组合的增量，不能计入虚构的飞抵购机场收益。

### 5.2 股票窗口

现金不足储备先按每单位变现的未来收益损失升序卖股，只卖恢复储备所需股数。否则比较1–2股合法订单，选择正增量最佳者；原20股供应、城主4股、单城2/总6/最多3城全部检查。成功卖出的city本窗口不买回；steps>=8结束。原出售不因城市抵押而禁止，但无主/清算城市不可卖。不得在该阶段提交自救卖股动作。

### 5.3 航班、交易、拍卖

不飞和每个合法flight报价比较：未来最多两次移动的期望支出改善减实际机票，另计确实可能通过未来骰子触发的起点收益差，不计飞行当场起点/机场奖励/购买。改善>0且票款保留储备才飞，平分选不飞。

转入报价：确认本人为target、卖方持股、每城1股、城市有效及城主上限；支付现金不能透支储备。股份当前价值与有限增量减交易款>0才接受，公平价可在预期收益>0时接受；无价值改善拒绝。不发起新交易。

拍卖最大价=min(cash-reserve,含房价值+折现收入)，只按原最低竞价加价；当前最高者沿原end退出。直接出售按实际含房价格评估。不要把卖方80%实收误作买方折价。

监狱/冻结缴费比较恢复本回合经营价值、可能通过起点收入、移动支出与15000/5000费用；pay仍须保留储备，否则沿原roll/pass。不会借缴费主动触发自救。

### 5.4 自救及募资

按损失/实际变现金额比较合法卖股、抵押、拆房；抵押损失包括停止经营的预期收入、原利息与债务，到账本金不算利润；拆房计算名义资产减损减真实退款及减少的租金。股票数量为min(持有,ceil(欠款/现价))。每次成功后重新取快照，现金>=0马上结束。

仅当前引擎允许的未抵押城市可出售；优先损失小的城市、每城本局一次拍卖尝试，原服务器补全自救上下文，记录成功提交后才标记尝试。没有合法变现手段或尝试已耗尽才rescue_done。

购地现金不足时，只有目标评分正、合法抵押/拆房可在扣除损失后补齐价格和储备才进入/继续募资；每次最多规划2座可抵押资产和已有可拆房层级，不做递归组合搜索，逐步复核。募资不允许rescue_sell_stock；不能满足安全预算则cancel。建房资金不足不主动进入募资，本轮不新增建房募资策略。

fallback自救使用简单合法卖股→可抵押→可拆房→未尝试出售，仍保留售卖数量与阶段检查；其他阶段保守退出。失败两次沿原blockedKey与原超时机制，禁止无限重试。

## 6. 机遇/换路线

每项采用相同有限视野计算边际价值，选择最高者；新旧路线组合分别估值，收益严格增加才更换。不将方向名称当作固定难度或隐藏属性。

| 项 | 边际依据 |
|---|---|
| H1/H2/H3 | 本人可投资城市、预算、施工真实费用/上限、同色资格；H1在主动经营版本仅估真实优惠/可达价值 |
| H4 | 外部股份预计基础股息20%奖励、每圈1000额度；本人股份考虑实际额外奖励 |

| H6 | 持股他人城市的本人预计付租减免及每圈额度 |
| H7 | 只有值得付费飞行时才计票款优惠；无可用航班不虚构1500保底 |
| H8 | 未访问机场的预计骰子到达×2000，已访问/飛行不算 |

## 7. 验证与决策解释

新评估提供测试可读的候选类型、储备、分项评分与选择原因，不新增游戏弹窗或每轮日志刷屏。新增不少于24个固定语义场景，含成对变更风险/时间/价格/资产和排列顺序检验。开发前保留旧策略作为测试基线（来源固定到0f6d3cc，仅测试加载），报告差异与独立场景理由，不以“新评分更高”自证。

测试必须调用原normalizeAction及必要apply/runAction核验许可、现金和阶段推进；旧测试中“必不飞”“必拒绝”“固定先买本城股票”等默认策略断言需改成相应明确局势的语义验收，不能仅删断言。

CPU固定100快照，输出P50/P95/max、Node版本和机器信息；不模拟100局。普通/快速各一条有限受控联机轨迹，最多24次电脑决定，达上限停止并说明覆盖范围。三端复用原bot浏览器测试。新增测试纳入原自动发现和CI，不创建独立无人执行的验收脚本。
