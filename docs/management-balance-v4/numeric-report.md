## 结论边界

- 固定输入中最优增量净资产分别出现：订单38、投资25、建设45个局面。这些是人为场景计数，不能称为胜率。
- 当前v3在优惠组合输入中出现80项无租金建设估值正增益；候选实际最低150%后，在640项建设检查中均没有正增益。
- 首次远程建设后第3次本人起点结算后还必须换城；6圈内持有两城时最多两次额外远程升级，仅持一城只能成功一次，普通落点建设独立。
- 订单2次兑现后净现金504–2000；不再依赖他人落点，但需要目标持续有效。
- 股价下降时可能亏损；奖金只来自实际股息，有30%/1500上限，无法保证本金或利润。
- 建设仍适合高客流和长持有，但资本占用更高。订单更容易快速兑现；投资依赖他人经营表现。
- 即时封盘：订单未赚收入不计值、股票没有现金返利、建设优惠不使新增估值高于成本。
- 尚未实施冷却/订单/奖励份额引擎，没有验证正式请求、真实落点或三端动作；全部开发检查仍未标通过。

## 模型假设

- 现金足够，城市持续归属且未抵押
- 每个个人圈按固定8次本人回合模拟，订单两次收款已兑现；未兑现另测
- 投资目标与本人城市基础地价相同，目标0级，正常派息在奖励到期前发生一次
- 分红按当前源代码标准租金/20%分红池/20股计算；订单和主动投资奖励使用候选公式
- 股票一次4股，价差仅在观察期末指定±20%/0%，不是随机预测
- 建设只比较一次升级，订单只比较一单，投资只比较一次买入；重复行动能力独立列示
- 建设增量租金含期末归城主的待结收益，现金回本使用全部结算后的理想值，不代表当场可用现金
- 不包括随机骰子、付款者破产、普通落点建设、股票清算与强化分红叠加；这些需开发后引擎验收
