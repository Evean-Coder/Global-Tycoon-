# 股票操作时限与列表稳定性 Spec

日期：2026-10-11。状态：2026-10-11用户统一批准开发；实现与实际验证见 acceptance.md。

流程依据：用户要求后续问题先整理完整四份开发文档，文档由开发者自审，最终开发询问用户。

## 背景与目标

玩家反馈快速模式经过起点购买股票时间过短。当前股票窗口只有20秒，需要阅读多个城市的报价、经营情况和持股额度，再选择股数并确认。为股票操作单独提供60秒，明确展示实际剩余时间，减少被动超时。

补充反馈：普通、快速模式在手机端点买股“＋”后股票列表向上跳动，影响连续选择。本轮同时保证调整股数时当前城市、滚动位置、焦点和已展开说明稳定；保留原股票交易规则与操作顺序。

## 功能需求

- F1 快速模式每个新起点股票窗口最多60秒；普通模式股票时限维持现状。
- F2 同一股票窗口只有一份期限：查看资料、调整数量、报价变化、无效请求、重复请求、切换转让面板及返回不能补时；有效交易后若窗口继续，也不能重计。新起点窗口才获得新时限。
- F3 发起转让期间，原股票窗口时间继续消耗。接收方确认沿用最多20秒并受整局剩余时间约束；拒绝或确认后恢复原股票窗口剩余时间，已耗尽则按原超时路径结束股票操作。原窗口到期不自行取消仍合法进行中的接收确认。
- F4 股票弹窗内清楚显示本次决定剩余时间，暂停时明确说明；无需关闭弹窗寻找倒计时。与现有决定倒计时使用同一服务端时间来源。
- F5 股票超时沿用原放弃交易处理；未提交草稿不自动成交，已成功交易保持。整局30分钟到时仍优先封盘，未确认事项按原规则取消。
- F6 规则速查与开发说明同步股票60秒、转让确认20秒及整局截止优先，避免仍宣称所有快速普通决定均为20秒。
- F7 两种模式调整买入/卖出股数时，不重建整份股票列表，不跳回顶部、不移动到其他城市；当前城市保持可见，继续点击原控件即可。按钮达到额度变成禁用也不触发意外滚动。
- F8 同一股票窗口的报价及状态更新保留仍存在的城市卡片、已展开说明和合理焦点位置，所有城市的可买额度及费用汇总及时更新；查看资料/转让编辑后返回保持原草稿和浏览位置。窗口结束或切换新窗口时不沿用旧窗口位置、焦点或草稿。

## 非功能需求

- N1 沿用现有技术栈、数据源、事件、身份与重复请求校验，不增加运行时依赖。
- N2 三端倒计时文字清晰可见；不新增独立计时循环，不每秒播报干扰辅助技术。
- N3 重连和既有离线暂停规则继续使用原剩余预算；总时钟仍不暂停。已打开的窗口不因重复同步重新分配60秒。
- N4 用固定时钟、必要回归和一个受控浏览器流程验证，不运行大量完整对局，未验证的条目不标通过。
- N5 使用触屏、鼠标和键盘均可调整股数；焦点保留不能强制页面滚动或干扰玩家之后手动滚动。

## 本轮不做

不改股价、分红、买入额度、购买入口、股票草稿及自动结束语义；不延长一般决定、自救或机遇时限；不改离线推进、人机思考等待、30分钟结算或移动端布局。股票倒计时提示不作为网络延迟修复。
