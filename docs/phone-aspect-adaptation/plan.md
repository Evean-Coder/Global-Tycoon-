# 主流直板手机连续适配 Plan

日期：2026-10-26。基于独立Spec，用户已回复“开始”，按此方案实施。基线dda4c80；不迁移服务端状态。

## 1. 已核实的接入点

- BoardLayout.mode已识别compact-landscape，geometry固定12×11／42格，位置映射不需要改变。
- syncResponsiveLayout当前固定右栏25%，以boardWrap已布局尺寸判断强制放大；自动回退和compactMapZoom手动选择混在同一CSS类中。
- resize／visualViewport事件已监听，但布局仍主要读innerWidth／innerHeight。部分弹窗仅在max-width:1200px媒体条件下使用横屏布局，宽屏手机会落回旧规则。
- 编号栏4px且允许逐字换行，造成10–41号竖排。BoardPresentation已有唯一的两至三字简称与真实全名，继续复用，不重新取容易混淆的简称。
- 棋牌图片／棋子已有实际锚点定位、ResizeObserver和字体就绪处理；资产／股票／资讯已有稳定节点补丁、草稿和阅读恢复。
- v47保留整页左padding=0，本轮不能悄悄回到整页左安全区空条。

## 2. 模块划分

### A. 可见区域适配器

在原客户端收集layout视口、visualViewport、缩放、可用边距、物理方向和是否手机，合并resize、visualViewport.resize/scroll、fullscreenchange、orientationchange与相关ResizeObserver事件。一次animationFrame至多完成一次读→计算→仅必要写入，不引入运行时依赖。

缩放接近1时，先建立布局矩形、visualViewport可见矩形与原样式采用的安全矩形，取有效交集；不能先取已经扣边距的可见宽高又减一次同一边距。无效／缺失接口回退到innerWidth／innerHeight和原动态视口单位。不支持dvh时JS计算尺寸仍可使用。原始浏览器值与最终采用值分开记录，不能用物理像素除一个猜测的DPR。

对局主区域保持左对齐，整体不用负margin／transform移动。模态层使用可见矩形约束，键盘导致可见视口缩小时将正文和操作区置于可见范围。offset只用于模态层／当前输入可达性，不能把全页随键盘滚动反复平移。

visualViewport.scale大于1.02时按用户缩放处理：保留上次未放大的布局尺度，不用更小的visual宽高重排来抵消放大，允许原生平移／滚动阅读；旋转后再确定新基准。系统显示缩放导致的CSS尺寸变化正常重新布局。不得设置user-scalable=no。

### B. 纯布局策略

新增public/phone-layout.js，UMD形式同时供浏览器与Node测试，无DOM／资金依赖。

输入ViewportSample：layoutWidth/Height、visibleWidth/Height、offsetLeft/Top、scale、phone、physicalLandscape、safeTop/Right/Bottom、userZoom、previousUnzoomedSize。所有尺寸必须有限非负；无效输入回退原安全布局，不产生NaN。

输出PhoneLayout：density（standard/short/constrained）、headerHeight、footerHeight、sideWidth、boardWidth/Height、tileLayout（stacked/inline）、编号／图标／字号变量、mapMode（overview/scroll/zoom）、reasonCode、modalRect。纯派生，不保存第二份游戏状态。

先评估能完整放下棋盘的候选，再选择较舒展的候选；不能为了显示更高顶栏而把原本放得下的棋盘推入滚动。具体预算：

| 项目 | 方案 |
|---|---|
| 顶栏 | standard为44px；短屏为24px纯状态条，原规则入口由更多中的规则继续提供。短状态条没有小尺寸按钮或伪装44px目标 |
| 底栏 | 常规单行44px，保持骰→经营→资产→银行→更多。极端窄窗口若五个44px目标放不下才分两行，并重新计算地图空间 |
| 其他高度 | 原页面上下4px内边距及主区与操作区4px间隔合计12px；顶部／底部实际安全区在此前扣除一次 |
| 侧栏 | 优先128–240px，空间不足允许逐步缩至72px；窄侧栏的键值改上下排列、长名和超长数字换行、自然高度滚动，完整数据可从原更多大窗阅读。低于96px时操作按钮改单列，不能仍用两列挤出小于44px宽的目标 |
| 棋盘 | 每格高至少15px；普通宽度内短名至少8px。图层边距／格间距计入预算，不按12个名义格宽直接估算 |
| 格内布局 | 高度至少24px时上下两层：上层编号／图标，下层短名；更矮时单行独立列，容纳最长三字简称。单行保守格宽39px、编号栏8px／等宽6.5px、图标5px、短名8px；空间增加时编号至少8px、图标至少8px、短名9–12px |
| 概览底线 | 单行格保守棋盘483×180px；上下层格保守399×278px。都含边框、padding及间隔。测量字体后若文字仍溢出，使用更合适候选或可读回退，不能藏文字伪造通过 |

例如有效568×260：24px顶栏＋44px底栏＋12px间隔后剩180px；去掉左右4px及4px主区间隔后，可给棋盘484px和侧栏72px，满足原布局完整概览。这里的有效区域已经扣除浏览器及采用的系统边距。

空间不足时mapMode=scroll：保留完整棋盘结构，使用上述较小的可读底线独立滚动，不直接强制553×366的大地图。用户主动放大时mapMode=zoom，沿用至少553×366及较大格子的阅读方式。

自动回退与userZoom独立。可用空间恢复且userZoom=false时立即选回overview；userZoom=true只由用户恢复。更多按钮文案按状态显示“放大地图／恢复默认视图”，自动受限时不承诺“当前必定能全图”。只比较未被子地图最小尺寸反向撑大的外部可用区域，避免测量反馈导致粘住或振荡。

### C. 页面、地图与状态呈现

原compact-game控制手机适配作用域；新增density与mapMode属性／CSS变量，避免按浏览器UA或精确机型切样式。PC／常规平板仍走原布局。宽屏手机的弹窗依据phone状态，不能再被1200px媒体上限排除。

复用原BoardLayout及BoardPresentation、placeBoardSurfaces/renderPieces；只改变样式和实际可用矩形。序号改为完整不换行；图标和简称不重叠。中央地图仍100%铺满内框，资讯／资产台账等高、左／右位置保持，内容自然滚动。不会因资料多而撑大整个gameMain。

短顶栏状态保留当前玩家、决定期限、快速总时限及必要的离线／自救原因。详细经营状态和规则可从原更多取得；不把关键倒计时藏进菜单。角色为纯状态时移除原小高度点击语义，玩家详情从右栏／更多访问。

大厅／房间按可见高度允许整页滚动，不套用对局overflow:hidden；输入聚焦后仍可到达创建／加入／开始。对局方向门禁继续依据原物理方向策略；可见区域变矮不能被当作手机旋转。

### D. 弹窗、键盘与阅读

为通用、股票、机遇、经营、扶持、规则、回放与回顾共用可见矩形预算。标题不参与压缩，正文minmax(0,1fr)并自然滚动；一般正文可见高度至少80px。最小受限区无法同时容纳所有操作时，底部操作区高度有上限且可独立滚动，各按钮仍44px，正文不跟着按钮数量被压为零。卡片不再各自套入垂直滚动。

股票窗口按可用宽高选择列表＋侧栏或列表＋底部操作，先保证一张卡的加减控件及操作区能读取；不再固定190px侧栏去挤不足宽度的列表。所有报价、草稿、回执和窗口generation沿原路径，不新增提交或确认。

初始机遇、换路线与经营类型卡按宽度安排列数；同一窗口正文滚动可读全部候选，按钮不被固定底栏覆盖。路线／经营子页返回与放弃／关闭的位置继续沿原语义。银行、自救、募资的资金缺口与股票数量操作仅调布局。

调整样式／视口前后使用原稳定节点和阅读恢复，不以viewport变化调用重建式渲染。强制决定仍可按原优先级接管，阅读帮助不能关闭正在进行的合法决定。

### E. 只读适配信息与主动全屏

原更多新增“屏幕适配”区域，显示当前概览／滚动／主动放大及简短原因，复用地图放大入口。可用时提供用户点击“尝试全屏”，与强制横屏检测解耦：浏览器拒绝或不支持时保留当前可玩界面，不重试循环。

诊断复制只允许布局尺寸、采用边距、缩放、当前策略和功能支持标志；不复制整个gameState、localStorage、重连token、房间码、玩家身份、报价或私有任务，不自动发送网络请求。

## 3. 数据流与接口约定

可见区域／物理方向变化→合并读一次→PhoneLayout计算→仅变更的CSS变量及状态→原锚点／棋子定位→必要的输入可见性恢复。

1. 所有适配信息为客户端派生；服务端、Socket事件、action载荷、record格式和游戏规则版本不变。
2. userZoom按当前gameId的UI状态管理，新局重置；自动mapMode不写成用户偏好，不持久化旧尺寸。
3. 样式应用前后原股票／经营／出价草稿不变；不触发sendAction或重建整个棋盘，倒计时继续服务端值。
4. 布局只写结果不同的值；坐标取实际同一坐标系，稳定后400ms内收敛。循环观察超过预算时停止重复写、保留可滚动布局并在诊断说明，不让整页卡死。
5. 图标／颜色仅呈现已有类型与ownerId；不把侧栏颜色、棋子位置或客户端尺寸当成权限依据。
6. 缺接口使用保守尺寸／滚动；用户主动缩放、系统放大和失败全屏均不产生额外游戏动作。

## 4. 方案比较与选择

| 方案 | 结果 | 结论 |
|---|---|---|
| 增加机型／比例媒体查询 | 能补几个截图，浏览器工具栏变化后仍可能失败 | 不采用 |
| 整页按一个倍率缩小 | 可放进矩形，但按钮和输入同时变小，用户缩放可能被抵消 | 不采用 |
| 可见区域预算＋弹性分区＋可读回退 | 保留原棋盘、状态和操作，覆盖连续尺寸且有明确边界 | 采用 |

## 5. 验证及发布

- viewport-matrix.json计划504组纯布局扫描，基于12个比例采样×7档CSS短边×3档工具栏损失×两模式。22:9为压力，实际参数不是504个设备规格，也不是504场游戏。
- 补充小边界、1280／1467宽屏手机、真实源比值、非手机同尺寸、系统边距、DPR及动态事件的成对覆盖；不做全部维度笛卡尔积。
- Chromium跑完整矩阵；Playwright WebKit跑代表尺寸、键盘接口缺失／缩放与关键弹窗，新增专用命令及CI安装。WebKit测试不是Safari实体机认证；UA替换更不能代表真实内核。
- 每种弹窗族覆盖低高度、窄宽度和宽屏手机组合；少量真实双Socket动作验证草稿／报价／回执和期限，不跑大量完整对局。沿用受控时钟，避免再次遗留真实heartbeat。
- 真实荣耀X50／QQ、Android主流浏览器、iPhone Safari与系统浏览器的工具栏／键盘／切口仍需实体机反馈。自动与人工检查分别记录；无法取得设备时留未测项，不声称全市场所有机型都已实测。
- 同步新模块、index、sw与精确资源查询版本，拟PWA v48-phone-fit／20261026-phone-fit；旧局不强刷。按AGENTS.md提交本轮文件并推送，核对完整CI与Render资源／自有临时对局，保留无关工作区。
