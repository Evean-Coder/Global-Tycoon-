# 环球资讯、经营机遇与股票优化 Plan

> 版本：1.0｜日期：2026-10-01｜依据：已批准的 spec.md v1.1。全部章节及整份 plan.md 已批准；用户在整份审批请求后回复“继续”，进入任务拆解。尚未进入实现。

## 设计依据

实现已批准的 F1–F15、N1–N6 与 AC1–AC23，包含五类资讯、十二项经营机遇及股票规则；纳入已经批准的 S1 产权结算报价例外。所有新开局使用统一规则，游戏内沿用自然名称。原基础棋盘、单骰及未列为差异的操作流程保持原语义。

本文定义组件、状态、动作与结算接口，以及调用顺序和技术选择。后续 task.md 拆解具体步骤，checklist.md 定义执行与观察证据；四份文档全部批准后才进入开发。

## 架构概览

继续采用现有 Node.js 服务端、Socket 通信和原生 HTML/CSS/JS 前端。服务端维护唯一对局状态，所有成功动作在完整校验后统一提交；前端只提交意图并展示结果。新对局使用统一规则版本，旧对局按已有版本兼容，不在房间提供玩法选择。

### A1 对局编排与完整轮次

在现有规则引擎接入独立的完整轮次追踪器，记录本轮应行动、已完成和已出局玩家。正常结束、自动跳过和清算后的继续回合都经过同一边界检查；断线暂停与回合内子阶段不推进轮次。轮次边界负责完成租金观察窗口、经营报价更新、资讯推进和阶段性机遇选择；先处理终局与未完成清算，再允许下一轮行动。原显示轮数、抵押计息和晚期监狱规则保留原语义。

覆盖 F1、F2、F4、F10、F13。

### A2 资讯与机遇管理

以固定效果目录和各自状态管理五类资讯、地区轮换、预告、十二项机遇、三次选择及一次重选。候选生成使用可注入的随机源，遵守方向覆盖、排除与次数条件；待选择状态保存全体参与者、本人候选、已提交选择和阶段身份。全员完成或超时后统一应用并公开，之前不发放能力或即时奖励。已选能力、个人额度及机场首次访问记录独立于地产和股份。

覆盖 F3–F6。

### A3 费用、效果与额度结算

集中提供租金、建房、机票、拆房返还和经营奖励的计算及结算明细。计算阶段只读状态，返回原价、各项贡献、总上限、最终金额和所需额度；成功动作统一提交金额、房级实际成本及额度变化。原建房和新增远程施工共用费用计算，分别保留各自资格。普通、自救和募资拆房共用实际建造成本返还规则。所有起点奖励、骰子直接到达奖励和银行补贴通过明确的触发边界执行。

覆盖 F6、F7、F9、F12。

### A4 股票、分红与资产口径

集中处理经营报价、最近三轮租金、待分红、股票窗口累计限额、股份转让、产权易主及清算。城市租金分为城主现金和独立待分红；派息、正常易主、归银行清空和终局分别使用规格规定的结算边界。交易一次校验整单，提交后同步更新份额和现金。所有服务端排名、记录与前端资产展示使用同一估值口径；报价及费用解释由服务端提供，前端不另算一套规则。

覆盖 F11–F15，以及 F7、F9、F10。

### A5 身份、私有投影与共享计时

沿用现有房间、身份校验和动作入口，新增同时选择时按连接身份判定本人操作权限。将当前共用快照改为按接收者生成的白名单投影：公开资讯、已生效能力及完成状态共享，仅本人收到自己的候选和提交状态，未公开结果与未来序列不广播。共享选择使用同一个三十秒决定计时，提交和重选不改变决定身份；超时一次补齐未提交者并统一结算。断线暂停及重连恢复使用现有时钟机制。

覆盖 F5、F10，N1、N3。

### A6 三端展示与操作入口

沿用现有渲染、完整棋盘、资产卡、股票窗口和弹窗体系，增加“环球资讯”“经营机遇”“已选机遇”、费用明细及股票变化原因。选择弹窗属于强制阶段；主动机遇入口按服务端资格显示可用状态，不覆盖原操作。PC、平板和手机采用同一状态与操作含义，分别适配布局、滚动、键盘及触控。所有新增产品文案遵守 spec 的自然名称约定。

覆盖 F8、F15，N4。

### A7 记录、兼容与验证

成功提交同时产生结构化结算记录，包含规则版本、公开资讯、已公开机遇、费用贡献、基础分红、银行奖励、保留经营收益及清算款，避免仅靠解析日志文字统计。记录生成前统一处理残余分红，且终局只提交一次。旧记录缺失新字段时按已有数据展示，不补造收益；未使用新规则的旧状态走兼容处理，后续新开局一律采用新版本。

验证覆盖纯计算数值、完整轮次与选择状态、动作原子性、多人网络隐私与计时、三端界面及完整端到端流程；先保留并验证工作区已有的动作安全改动，再接入本轮功能。

覆盖 F1、F9、F10、F14、F15，N1–N6。

## 依赖方向

```text
前端操作意图
    ↓
房间身份与动作校验
    ↓
对局编排（候选状态内执行）
    ├─ 完整轮次与资讯/机遇推进
    ├─ 费用和奖励计算
    └─ 股票、分红、产权及清算
    ↓
统一提交状态与结构化记录
    ↓
接收者白名单投影＋决定计时
    ↓
三端渲染
```

固定目录与基础金额计算置于底层；规则组件不调用 Socket 或前端，资讯与机遇的效果计算不反向驱动回合。跨组件触发顺序由对局编排负责，避免彼此调用形成循环。具体字段、动作协议与结算顺序将在后续设计段定义。

## 核心数据与接口

下述名称用于开发。玩家界面仍使用 spec F8 的自然文案。继续使用普通 JavaScript 对象，便于现有状态复制、Socket 投影及 JSON 记录，不引入运行时类型库。

### D1 对局身份、版本及推进状态

| 状态 | 字段与含义 |
|---|---|
| 对局身份 | `gameId` 每次新开局生成新身份；`ruleVersion: 2` 标识本轮规则；`revision` 每次成功提交递增，用于客户端识别状态先后，不用于阻挡其他玩家的同时选择 |
| 行动区间 | `turnId` 每次实际轮到一名玩家递增，自动跳过也有独立标识；`actorRevision` 按玩家保存其当前可操作状态版本 |
| 位移来源 | `movement` 保存当前位移身份、来源、骰子原始落点及落点奖励处理标记；起点股票子阶段后继续落点处理时沿用同一身份，机会卡或飞行位移不能冒充骰子落点 |
| 完整轮次 | `roundFlow: { index, requiredIds, completedIds, boundaryId, continuation }`；`index` 为当前新增玩法轮次，从 1 开始；身份列表使用数组，完成者不重复计入 |
| 安全边界 | `boundaryId` 标记已处理边界；`continuation` 保存选择结束后应开启的下一轮/下一玩家，仅服务端使用；连续跳过逐人经过轮次追踪，不跨过尚未处理的安全边界 |
| 终局 | `finalSettlementDone` 防止同一终局重复派发残余分红；原 `status`、`phase`、`rank`、`winner` 保留 |

完整轮次与原 `rounds`、抵押计息路径相互独立。新状态创建即进入第一次选择；选择完成后恢复首名玩家的原开局动作。旧状态缺少 `ruleVersion` 时按原规则版本解释，禁止仅补一个版本号就追溯启用新收益。

### D2 资讯状态与随机队列

`world: { status, active, preview, roundsCompleted, constructionUsedIds, typeBag, regionBags, lastType }`。

- `status` 为未启动、运行中或已停止；`active` 保存事件身份、类型、实际地区、开始边界与剩余轮数；`preview` 只保存已经达到公开时点的下一项。
- `roundsCompleted` 仅统计资讯运行后已经完成的轮次，用于第三次选择的六轮条件。
- `constructionUsedIds` 记录本完整轮已成功取得建设优惠的玩家，在新一轮刷新；它与个人每圈额度分开。
- `typeBag`、旺季及淡季独立的 `regionBags`、`lastType` 仅在服务端保存。随机抽取依赖传入的 `rng`，测试可固定输入，生产沿用项目随机来源。
- 当前事件和已公开预告可投影给所有人；袋序列、未到预告时点的未来项及随机源禁止投影或写入公开记录。

### D3 个人机遇与同步选择

个人状态为 `opportunities: { selectedIds, rerollsLeft, lapEpoch, usage, visitedAirportIds }`。

- `selectedIds` 保存已统一生效的 H1–H12 身份，不含本阶段尚未公布的选择。
- `rerollsLeft` 初始为 1，成功重选后扣除；不随阶段、起点、转让或重连刷新。
- `lapEpoch` 只在本人原起点结算时递增；`usage` 按机遇身份保存本圈成功使用次数或累计金额。H4、H6 保存已使用金额，H1/H2/H3/H7/H11 保存次数；H3 所有色组共享同一项。
- `visitedAirportIds` 保存选择 H8 后通过合格骰子落点已领取奖励的机场，本局不清空。H12 的一次性奖励与阶段统一生效标记绑定。

同步选择独立保存 `opportunityStage: { stageId, ordinal, participantIds, participants, resolved, continuation }`，原 `phase` 增加 `opportunity_choose`。

每名参与者的 `participants[playerId]` 保存 `candidateIds`、`candidateVersion`、`submittedId`、`submitted`、`replacedIds`。重选成功使候选版本递增，旧候选的迟到确认必须拒绝。全员提交或到期前，所选项只在该参与者自己的投影中出现；其他人只看到是否已提交。`resolved` 防止再次应用整阶段奖励。阶段结束后只保留已公开结果供记录，待选私有数据不进入终局记录。

### D4 城市、股票和交易窗口

| 状态 | 字段与含义 |
|---|---|
| 城市 | 保留原产权、房级、地区、颜色、抵押字段；增加 `buildCosts`，按从低到高每级保存实际建房支付额，拆房弹出最后一项 |
| 经营与股份 | 每城 `stocks[cityId]` 保留 `holders`；增加 `operatingPrice`、`dividendFund`、`roundRent`、`rentHistory`、`lastDividendPerShare`、`priceChange`、`listingEpoch`、`clearing` |
| 租金观察 | `roundRent` 累计当前完整轮该城有效租金；边界将其并入最多三项 `rentHistory`，无收入轮也写入 0，再按 spec F13 更新经营报价 |
| 当前公开价 | `price = operatingPrice + floor(dividendFund / 20)`；原 `price` 字段作为统一派生结果保留给既有展示，不允许其他路径单独修改；`priceChange` 区分经营调整与待分红变动 |
| 清算身份 | `listingEpoch` 每次归银行后重新经营递增，用于区分新旧股份及清算；`clearing` 暂停普通交易；清空与派息记录各自唯一结算身份 |
| 股票窗口 | `stockWindow: { windowId, playerId, prices, quoteVersions, listingEpochs, boughtByCity, boughtTotal }`；开放时建立报价与经营身份快照；普通交易保持报价；产权结算仅刷新受影响城市的报价、版本与资格；额度累计于窗口，买入城市数由 `boughtByCity` 正额项数量得出 |

`stockWindow` 不放在可能被转让、募资、自救替换的 `pending` 中。离开股票阶段处理转让或资产操作时保留同一窗口，返回时不重建窗口或刷新买入额度；`stock_done` 后关闭。普通买卖和股份转让不改变报价；产权成交派息、归银行清空或重新经营按已确认 S1 更新受影响城市的报价及资格。允许操作的城市仍按提交时产权及清算状态校验，报价快照不能解锁已失去资格的股票。

`stocks[cityId].holders` 是股份归属的唯一判定来源；保留原玩家 `stocks` 字段为同步派生镜像，供原界面兼容。每次成功提交验证镜像一致；市场剩余股数由 `20 - sum(holders)` 推导，不另存一份可漂移的市场份额。

新城市初始化 `operatingPrice = 0.2 × 地价`、待分红及历史为零。正常易主保留报价、历史、股份和 `buildCosts`；归银行清空按 spec F14 清除后再允许重新经营。旧规则已有房级没有成本数组时，兼容返还路径使用原标准费用，不伪造历史优惠。

### D5 金额计划、资产摘要与公开记录

计算结果使用 `SettlementPlan`：`kind`、`settlementId`、`baseAmount`、`effects`、`finalAmount`、`cashDeltas`、`fundDeltas`、`shareDeltas`、`quotaChanges`、`buildCostChanges`、`guards`。

- `effects` 的每项保存效果身份、计算基数、请求优惠、上限截取后实际贡献及现金来源；实际贡献为零不扣额度。
- `guards` 保存相关产权、阶段、候选/报价及额度依据；计划只在同一次服务端候选状态执行内生成与提交，不跨请求复用。
- 金额与股数须为安全整数，资金不足及负现金遵守原债务规则；溢出、格式错误和资格失败拒绝整项操作，不能保留部分账务。
- 结算记录区分 `city_rent`、`dividend`、`retained_income`、`opportunity_reward`、`stock_trade`、`stock_liquidation`、`build`、`demolish`、`flight`、`price_update`、`news`、`opportunity_selection`。
- 成功结算使用稳定的 `settlementId` 与来源动作、轮次边界、阶段或起点结算身份绑定；只有成功提交后进入 `room.events`，重复通知只重传已有记录身份。

`AssetSummary` 保存 `cash`、`propertyValue`、`airportValue`、`stockValue`、`retainedPending`、`total`。股票估值使用份额乘含待分红的当前价；城主待分配经营收益为该城 `dividendFund - floor(dividendFund / 20) × 存活玩家总持股`。该值计入总资产并单列，不能作为可支付现金。服务端生成各玩家资产摘要，前端、排名和终局记录统一使用。

新记录使用 `global-tycoon.game-record.v2`，保存 `ruleVersion`、完整轮次、公开历史、已生效机遇和结构化收支统计；旧 v1 记录仍按原字段读取，不制造不存在的收支记录。

### I1 Socket 动作协议与防重放

沿用 `action`、`gameState`、`timerStarted`、`gameRecord`、`error` 及现有房间事件。保留旧动作含义，新增动作只承担选择、重选及远程施工：

| 动作 | 专用参数 | 资格 |
|---|---|---|
| `choose_opportunity` | `stageId, candidateVersion, opportunityId` | 本人仍在当前选择名单、未提交、候选版本有效且选项属于本人 |
| `reroll_opportunities` | `stageId, candidateVersion` | 本人未提交、候选有效且本局重选余量足够 |
| `remote_build` | `cityId, quoteVersion` | 本人正常等待掷骰、拥有 H1、额度及城市资格有效，最终费用可支付 |
| 原 `stock_trade` | `windowId, orders`，每项订单含 `cityId, side, shares, quoteVersion, listingEpoch` | 本人股票窗口，按城市报价版本、经营身份、累计额度与整单资金校验；任一旧报价或旧身份整单拒绝 |
| 原 `stock_transfer` | 发起时携带 `windowId`，其余股份、现金、接受参数沿用 | 发起方及确认方各自按当前阶段身份校验；确认时重新核对双方状态 |

所有新规则对局的客户端动作都附带 `gameId, actionId, decisionId, actorRevision`。涉及费用确认的动作附带服务端 `quoteVersion`；每次展示时从本人投影获取，不能由客户端指定费用。身份从当前已认证连接解析，不接受客户端指定 `actorId`。

- `decisionId` 来自房间动作时钟，针对整个决定稳定；同步阶段重选或个人提交不产生新决定。
- `actorRevision` 只针对该玩家可操作状态；其他参与者提交不会使其候选过期。普通回合内成功资产操作使本人版本递增，但不重置原决定倒计时。
- `actionId` 由客户端生成并在同一请求重试时复用。服务端在当前房间保存有界去重缓存，按对局、玩家和动作身份隔离；同身份同内容返回原回执，同身份不同内容拒绝。已淘汰缓存项由决定/本人版本校验阻止再次执行。
- 缓存记录成功动作；失败后重试可重新校验。客户端确认成功前不自行扣现金、消耗额度、锁定已生效能力或连续提交依赖该成功的后续动作。
- 原股票“提交订单后结束窗口”改为等待交易成功回执再提交 `stock_done`，结束动作携带更新后的本人版本，避免失败订单关闭窗口。
- 同时选择不使用全局 `revision` 作请求门槛，避免一名玩家提交导致其他人的合法提交被拒绝。
- 超时默认及生命周期处理是内部入口，绑定当前决定/阶段，不冒用玩家连接，不接受客户端调用系统动作。

动作回执统一为成功 `{ ok: true, gameId, actionId, revision, actorRevision, decisionId }` 或失败 `{ ok: false, code, error }`。私有候选不随其他人的回执返回；旧规则对局继续接受原动作格式并使用原验证。

### I2 状态投影与时钟载荷

`snapshot(state, viewerId, clockView)` 返回白名单视图；`viewerId` 从服务端连接身份获取，缺失身份只能得到公开视图。

| 视图 | 内容 |
|---|---|
| 公共 | 原棋盘与玩家公开状态、当前资讯、已公开预告、已生效机遇、阶段参与者及完成状态、股票公开依据、统一资产摘要、公开结算事件 |
| 本人 `self` | 本人候选、本人提交结果、重选余量、候选版本、机遇额度、本人动作版本、股票窗口剩余额度、可用操作及报价明细 |
| 决定 `decision` | `gameId, decisionId, phase, secondsRemaining, paused`；选择阶段共用同一决定和剩余时限 |
| 禁止输出 | 他人候选或未公开选择、私有完整阶段对象、随机袋/序列、未来未预告资讯、内部继续流程、去重缓存、身份凭据 |

原 `pending` 也按阶段白名单重建，不直接复制内部对象。所有发送路径，包括正常广播、重连、掉线通知与终局前快照，都使用同一投影入口；不能在个别路径继续发送原整份状态。

`timerStarted` 保留原字段并增加 `gameId, decisionId`；前端忽略旧对局或旧决定的计时通知。重连快照直接携带剩余时间，暂停状态不依赖是否再次收到“新计时开始”事件。房间时钟使用单调时间测量剩余毫秒；毫秒截止时间不作为持久状态或客户端自判依据。

### I3 核心规则接口

接口均使用普通对象返回值；以下签名为实现约定。状态改动仅发生在服务端候选状态中，提交成功后才替换正式状态并发布记录。

| 接口 | 输入与输出约定 |
|---|---|
| `normalizeAction(state, raw, context)` | `context` 包含认证玩家和来源；返回规范化动作或错误，校验阶段、身份、版本与参数；内部来源不能从客户端参数获得 |
| `apply(state, action, rng, context)` | 在候选状态内执行已校验动作；返回 `{ state, events, rejected, error }`，任何失败使整项候选状态丢弃 |
| `completeTurn(state, playerId, turnId)` | 幂等记录回合完成并报告是否到完整轮次边界；未行动出局移除待完成要求，不撤销已经完成记录 |
| `processRoundBoundary(state, rng, events)` | 当前清算已完成且未终局时，完成租金窗口、报价、资讯及阶段触发；同边界只处理一次 |
| `beginOpportunityStage(state, ordinal, continuation, rng)` | 建立候选和全体选择名单；返回阶段身份，由房间时钟建立三十秒决定 |
| `resolveOpportunityStage(state, stageId, cause, events)` | 全员完成或真实超时后，默认补齐剩余选项并一次性应用结果；`cause` 为内部可信来源 |
| `quoteRent / quoteBuild / quoteFlight / quoteDemolition(state, context)` | 只读生成金额、效果贡献、资格与失败原因；租金需要付款人及城市，建房区分普通/远程，航班明确出发及目标，拆房读取末级实际成本 |
| `applySettlement(state, plan, events)` | 复核计划依据并提交现金、待分红、额度和成本变化；不自行推进回合 |
| `settleGoEconomy(state, playerId, goSettlementId, events)` | 按规格刷新本人额度、派发名下城市分红并处理起点经营奖励；原起点基础奖励及原圈购买逻辑仍由原流程负责 |
| `updateOperatingQuotes(state, completedRoundId, events)` | 按三轮收入和房级、抵押状态更新经营报价；以完成轮次身份防止重复计算 |
| `openStockWindow / closeStockWindow(state, playerId)` | 建立报价快照与累计买入额度，或关闭当前窗口；中间确认/募资子阶段不能重建，S1 结算只刷新受影响城市 |
| `planStockTrade(state, playerId, windowId, orders)` | 只读校验整单并生成股份、现金及累计额度变更；提交失败不能留下部分成交 |
| `refreshWindowCityQuote(state, cityId)` | 仅由产权成交派息、归银行清空或重新经营的已提交规则路径调用，刷新仍开放窗口中该城报价、版本与资格，保留窗口身份及累计额度 |
| `settleCityDividend(state, cityId, reason, settlementId, events)` | 原因区分起点、成功易主、银行清空或终局；返回基础股息、保留收益、额外奖励及报价现金成分变化，经营报价保持 |
| `transferCity / clearCityToBank(state, context, events)` | 统一执行产权前派息、新城主持股上限或归银行清算；涵盖直接出售、拍卖、破产与认输；同次成交/清算各项变化一次提交 |
| `settleFinalEconomy(state, endReason, events)` | 终止未完成选择与推进，结清全部残余分红一次，然后由原流程排名、生成记录 |
| `assetSummary(state, playerId)` | 统一输出 D5 资产摘要，供排名、快照与记录使用；不得将待分红再加到现金 |

### 本段自检

- 私有候选、提交状态和随机队列有明确存储与输出边界。
- 资讯每轮额度、个人每圈额度、股票窗口额度互不混用。
- 金额、分红、股份和实际建造成本有统一来源，派息不重复计价。
- 同时选择允许不同玩家独立提交；迟到确认、重复动作与旧对局请求可识别。
- 原 Socket 事件保留，新增行为仍走原 `action` 入口；旧状态与新开局的版本处理明确。

### S1 已批准的报价边界

本设计依据 spec.md v1.1：普通买卖及股份转让不改变窗口报价；产权成交派息、归银行清空或重新经营时，更新受影响城市报价、资格及版本，原累计买入额度保持。旧报价或旧经营身份订单整笔拒绝，展示新报价后重新确认。普通出售/拍卖仍按原流程结束回合，转让确认按原流程返回同一股票窗口，不新增出售后回流操作。

## 模块交互与结算顺序

### C1 动作校验、提交与发布

1. 从房间当前连接取得认证身份，核对对局身份及动作格式；离线暂停、终局和无权限请求不得进入规则执行。
2. 对已成功动作的相同身份与内容返回原回执；其余请求校验决定身份、本人版本、候选或报价版本及当前阶段资格。
3. 复制当前状态，在副本中执行规则与全部账务；结算计划在这次执行中即时生成和复核。失败丢弃副本及新记录，不同步新的决定时钟。
4. 校验现金/股数安全整数、城市份额及镜像、分红守恒、房级与成本长度、额度范围和阶段一致性；只在全部通过后提交正式状态、版本和结构化事件。
5. 按提交后的阶段同步房间决定时钟；同一决定保留原截止时间，新决定才给予对应完整时限。若当前需要全局暂停，在发布之前将时钟保持暂停。
6. 使用提交后的状态与同一时钟视图生成各接收者快照、公开记录和动作回执。客户端按版本渲染，等待成功回执后再发依赖该动作的后续请求。

```text
认证与版本校验 → 候选状态执行全部变化 → 不变量校验
                                         ↓ 成功
                              状态/记录一次提交
                                         ↓
                              决定时钟同步
                                         ↓
                              本人投影与公开投影
                                         ↓
                              三端状态渲染和回执
```

处理失败、重复请求和只读查看不改变计时；成功远程施工及同阶段资产操作也不延长等待掷骰时限。可合法引发新决定的原流程继续沿用完整时限规则。

### C2 新开局与首次选择

房主开始对局后创建新 `gameId` 与规则版本，初始化完整轮次、资讯袋、个人一次重选余量及股票状态，建立第 1 次同步选择。普通掷骰与资产动作暂停，房主解散保留。

全体完成或超时统一处理后，先将结果写为已选机遇，再初始化每圈额度并发放 H12 等本阶段一次性奖励；记录公开结果。随后恢复原首名玩家等待掷骰阶段，建立原等待掷骰时限。此时资讯仍显示启动条件，不提前解除首圈购置限制。

### C3 正常回合、跳过与完整轮次边界

正常回合的股票、落点、购买、募资、自救、出售与拍卖等续接沿用原规则。只有整个回合实际结束或自动跳过，才以 `turnId` 记一次完成；子阶段完成不算额外回合。

短期监狱连续跳过时逐人记录完成，检查是否跨完整轮次边界；不能让原跳过循环直接越过需启动资讯或机遇的边界。原轮数增量、抵押计息及晚期监狱计费继续走原触发路径，续接标记保证暂停选择后不重复执行这些原处理。

达到安全边界后依次执行：

1. 检查仍有多少存活玩家；若应终局，完成已成立的清算和应付后转 C9，不启动新资讯或选择。
2. 将完成轮的各城市 `roundRent` 写入三轮历史，包括零收入；更新仍经营城市的经营报价，清零本轮租金累计。
3. 资讯已运行时完成一次轮数扣减、预告或切换；尚未运行但原购置限制已解除时启动首个资讯。未运行的刚完成轮不计入资讯运行轮数。
4. 满足第 2 或第 3 次选择条件时，在资讯已更新的状态中建立选择；保存下一轮续接，暂停普通动作。
5. 无选择或选择结束后建立下一轮存活玩家要求，清空上一轮完成名单，刷新资讯建设优惠的每轮使用名单，再准备下一玩家原回合阶段。

| 资讯时间点 | 当前效果 | 选择与预告 |
|---|---|---|
| 启动边界，已运行 0 轮 | 首项剩余 3 轮 | 显示首项后进行第 2 次选择 |
| 完成第 1 轮 | 首项剩余 2 轮 | 不公开未到时点的下一项 |
| 完成第 2 轮 | 首项剩余 1 轮 | 公开第二项及地区 |
| 完成第 3 轮 | 第二项剩余 3 轮 | 切换为已预告项 |
| 完成第 5 轮 | 第二项剩余 1 轮 | 公开第三项及地区 |
| 完成第 6 轮 | 第三项剩余 3 轮 | 先切换，再进行第 3 次选择 |

报价的租金依据属于刚完成轮，费用作用于接下来新轮的资讯；事件切换不追溯改算已经支付的租金或费用。

### C4 同步提交、重选及到期

- 提交只锁定本人当前候选结果，递增本人版本，其他人候选和版本不变。全员完成前不发即时奖励、不公开选项，只更新完成状态。
- 重选先校验剩余次数和候选版本，再生成符合目录条件的三个新候选，整体替换、扣一次重选并递增本人版本；阶段身份和共享截止时间保持。
- 每次真实请求由服务端检查共享截止时间。截止后的迟到选择或重选不执行，内部到期处理补齐全部未提交者；截止前已提交者保持原结果。
- 到期默认项使用其当前候选第一个，包含成功重选后的当前候选。全员结果一次应用、发奖和公开，再恢复阶段保存的原继续流程。
- 出局/生命周期移除参与者时，不给被移除者应用待选能力；重新检查终局优先级和剩余参与者是否全部完成。普通断线只暂停，不移除参与者。

共享时钟的决定键为对局与选择阶段身份，不包括个人候选版本、提交人数或当前轮到的玩家，因此合法重选与提交不会重新开始三十秒。

### C5 位移、起点及落点奖励

骰子与成功掷骰出狱创建带来源的位移身份，保留原落点。正常实际起点结算沿用基础奖励、每圈购置及首次绕圈处理，并按以下顺序接入新增经济：

1. 刷新本人机遇每圈额度，只刷新该玩家，不刷新本次收到股息的其他股东额度。
2. 对本人名下城市累计资金派发基础分红，按各存活股东已有 H4 剩余额度追加奖励。
3. 核对本人 H5/H9/H10 条件，发放实际符合的起点经营奖励。
4. 原股票窗口入口在上述处理后开放，报价使用派息后的当前价；原落点/结束续接保留。

初始位置是起点、首次选择完成、普通飞行及其它未执行原起点结算的位移不触发额度刷新。继续落点处理时，H8 仅对骰子原始直接机场落点执行一次，奖励在该机场原落点费用或交互前入账；经过起点股票子阶段或自救恢复不会再次领取。机会卡与飞行位移不满足 H8。

### C6 城市租金、优惠费用及拆房

城市租金先取得原标准租金与资讯调整，再依次计算 H6、H11 的个人减免和额度。一次提交扣租客最终金额、记录银行补足，并把完整资讯后租金拆为城主现金与城市待分红，同时累加本轮租金观察数据。

原现金变负流程继续成立：结算已记账后进入原自救，不在每次自救操作或恢复落点时重新计租、补贴或分红。未成立结算不写收入和额度。抵押城市零租金；机场费仍走原费用，不进入城市分红。

普通建房和远程施工复用同一最终费用计算，优惠贡献依次为资讯、H2、H3，支付成功后一次记录实际建造成本、升一级并扣有正贡献的次数。普通入口按原方式结束或继续回合；远程施工保留当前等待掷骰决定，不掷骰、不结束、不延时。

普通、自救和募资拆房按末级实际支付成本的 60% 返还，再降低房级、移除该级成本。费用折扣和建拆操作不直接上调股票报价；房级变化在下一完整轮边界生效于经营计算。

机票按资讯、H7 的贡献及总上限计价，免费航班不消耗 H7。资金不足时保留原机票债务和自救续接行为，不额外增加飞行或机场购买资格；其它航班移动顺序沿用原代码。

### C7 股票买卖、转让及报价更新

起点派息后建立一个窗口身份、报价表及累计额度。市场整单先核对报价/经营身份、每城单一方向、持股、市场余量、城主上限、累计买入城市与股数、净支付能力，再一次提交买卖双方份额及本人现金。

卖出后继续买、拆单提交和转让确认返回都使用同一累计额度，不给城主发旧规则额外回款。转让发起保存原股票续接，接收方接受时复核双方存活、现金、持股及城市资格；成功同时提交股份与协商现金，拒绝沿用原返回流程，不产生分红。

涉及 S1 产权结算时，城市股价与交易资格同步刷新，并使旧报价确认失效；不能让原窗口缓存保留已派发的股息。普通直接出售或拍卖按原流程结束回合并关闭窗口；只有原代码返回股票阶段的子流程恢复同一窗口。窗口关闭后迟到交易整笔拒绝。

客户端在订单成功回执后才发结束窗口动作；失败保留界面草稿，显示原因及最新报价，不自动变更订单价格或结束窗口。公开列表、资产卡和记录同时使用新的服务端资产摘要。

### C8 产权成交、出局及归银行清空

普通直接出售/拍卖成功先核对成交前可支付现金、购买资格及全部条件，不能预先用尚未到账的股息为不合格成交解锁。在同一副本内派发已有分红、完成原成交收付、转移产权，保留实际成本与经营历史，并按派息后报价处理新城主超四股部分。失败不提前派息；原卖方比例、竞拍费用与回合续接不改变。

已经成立的出局先按原规则标记、作废本人股份和停止本人机遇，再进行城市资产清算；收到新派息不撤销出局。原救济金及排名先后沿用原流程，资产判断改用统一估值。出局者尚未行动从本轮要求中移除，已经完成记录保留。

正常拍卖易主保留其他存活玩家持股，死者的保留经营收益归银行。城市归银行并清空时，先对存活股份派息、余款归银行，再按经营报价一半支付存活持股清算款，最后清空股份、房级、实付成本、历史和资金；每项有同一经营身份内的唯一结算标识。以后重新经营使用新经营身份和全新二十股，不恢复旧股份。

清算队列结束前不插入资讯切换或机遇选择；其后再检查终局与回合边界。原出售/拍卖基础估值不因本轮优惠而改变。

### C9 正常终局与解散

正常最后存活者结算、房主解散以及原生命周期要求的结束统一进入终局经济处理。停止普通动作、资讯推进和未完成选择；未统一生效结果不进入能力列表，不发本阶段奖励。

先完成已经成立的清算并向存活股东处理全部残余基础分红，经营中的城主取得保留收益；H4 仅使用各人的现有剩余额度。不得在这里刷新每圈额度、发起点奖励、重新抽候选或修改已经成立的出局。

残余资金归零后使用统一资产摘要执行原排名规则，最后生成并保存记录、发布结算及清除时钟。重复终局请求返回已有结果，不再次派奖或重写同份记录。

### C10 断线恢复、旧数据与三端渲染

任一存活玩家断线立即保留剩余毫秒并暂停所有普通动作及选择；广播使用各自白名单投影。重连重新认证并接管本人连接后，恢复原候选、提交状态、重选余量、额度、窗口预算和状态版本，未全员恢复在线时继续暂停。

全员恢复后从原剩余时间续计，使用相同决定身份；重连不触发目录抽取、圈额度刷新、派息或奖励。恢复快照含计时与本人信息，即使原决定没有重新创建也能正确显示倒计时。

新状态按版本识别，旧对局/记录沿用原数据与入口，缺失新增内容时兼容展示，不补算选择或收益。三端按同一投影更新棋盘、资讯、资产、股票和当前强制弹窗；候选提交后显示已确认等待，错误保留当前操作，焦点与触控行为沿用已完成的前端可用性设计。

### 本段自检

- 三次选择、事件持续/预告/切换和报价更新的边界先后明确。
- 本人圈额度、其他股东额度与共享选择时限不因旁人动作刷新。
- 租金、派息、建房、拆房、股份清算与终局均有一次提交和重复处理保护。
- 原出售结束回合、原自救与机票债务续接明确保留。
- 正常发布、掉线和重连均通过同一私有投影；记录仅保留已公开结果。

## 关键技术决策与模块落点

### 技术决策

| 编号 | 决策 | 采用方式与理由 |
|---|---|---|
| K1 | 沿用现有运行方式 | 继续 Node.js/CommonJS、Socket.IO 和原生 HTML/CSS/JS，不增加运行时依赖；规则组件使用普通函数和对象，接入原回合及房间体系。 |
| K2 | 服务端一次提交 | 保留现有 `structuredClone` 候选状态模式。动作执行、清算与终局经济处理同步完成，不在中途等待网络或文件写入；提交前失败整项丢弃，提交后才广播或记录落盘，避免半笔交易。 |
| K3 | 金额计算与取整 | 所有对外金额、份额与额度为安全整数。百分比和比值用整数分子/分母表示；内部乘除可使用 `BigInt`，四舍五入在正额基数上计算，派息每股向下取整，再将安全结果转为 Number；BigInt 不进入状态、Socket 或 JSON。所有增减后复查安全范围。 |
| K4 | 固定效果目录与有限抽取 | 五类资讯和 H1–H12 放在固定目录，条件、类别与自然名称一起维护。三候选从满足排除规则且覆盖至少两方向的合法三项组合中抽取；最大十二项只有 220 个组合，避免无界重试或不合格兜底。重选先排除旧三项与已选项，再抽取。 |
| K5 | 随机源与隐私 | 生产继续使用现有 `crypto` 随机来源，测试注入固定随机序列。资讯五类袋、旺淡季地区袋及骰袋独立保存；新组首项从不同于前组末项的类型中选取，再洗其余项。只有当前效果与到期预告投影给玩家。 |
| K6 | 独立轮次及共享时钟 | 新完整轮次不替换原 `rounds`，只在原回合结束及自动跳过的安全接点挂接。复用房间单调时钟，选择三十秒、原决定沿用原时长；共享决定键以阶段身份为依据，个人提交和重选不能换键或续时。 |
| K7 | 成功请求去重及过期保护 | 房间保存每名玩家最近 128 个成功动作的身份、规范化内容指纹和回执；新开局清除旧缓存。缓存命中先校验连接身份，再返回原结果；缓存淘汰后由对局、决定、本人和报价版本阻挡旧请求。支持重连复用动作身份，不提供跨重启持久去重。 |
| K8 | 按接收者白名单投影 | 新投影组件统一负责公共/本人状态。原 `snapshot` 入口转委托，正常广播、掉线、重连与结算统一使用；没有认证身份时仅公开投影。前端操作资格和价格明细从本人视图读取，界面校验不替代服务端校验。 |
| K9 | 股票与估值单一来源 | 股份以城市 `holders` 为准，原玩家持股列表为派生镜像；公开价由经营价和待分红推导。股票窗口身份与预算独立保存，S1 仅刷新受影响城市；资产摘要由服务端共用函数生成，终局和记录不另写公式。 |
| K10 | 兼容按版本识别 | 新开局一律规则版本 2，旧状态缺版本按原规则处理；新记录为 v2，旧记录继续显示已有字段。保留原规则需要的分支，不在大厅提供版本或模式选择；兼容不承诺服务器重启恢复存活对局。 |
| K11 | 原生界面及缓存更新 | 继续现有棋盘、资产、弹窗、焦点管理和媒体查询，机遇选项使用原生按钮；新增产品文案统一使用自然名称。HTML 中客户端/CSS 静态版本与 Service Worker 缓存版本一并更新，防止旧缓存脚本发送新规则不支持的动作格式。旧脚本请求新对局时返回可理解的刷新提示，不能降低新规则校验。 |
| K12 | 分层验证与证据 | 复用现有 `node:test`、Socket 客户端和 Playwright。纯数值、轮次/选择状态、网络身份/隐私/计时及三端界面分层验证；随机和时钟可注入。保留动作安全验证，旧断言仅按已批准差异调整，不用批量改预期隐藏回归。证据明确模拟视口、实际缩放或实体设备范围，功能通过不表述为平衡已验证。 |

货币取整示例沿用 spec：建房 12000 叠加三项优惠最终支付 8400，拆该级返还 5040；租金 10000 个人减免后租客付 7200，银行补 2800，城主即时 8000、待分红 2000；经营价 4000 和待分红每股 100 派息后报价为 4000，持两股派息后卖出合计 8200。

### 模块落点与依赖

模块职责与依赖如下；每个文件的修改步骤与验证命令在后续 task.md 拆解。

| 文件/组件 | 职责与依赖 |
|---|---|
| `src/gameplayCatalog.js`（新增） | 固定资讯和机遇目录、自然名称、常量及目录检查；可读取棋盘地区元数据，不依赖规则编排。 |
| `src/roundFlow.js`（新增） | 完整轮次要求、回合完成身份、边界及续接状态；不发送网络消息，不调用资讯或股票模块。 |
| `src/worldEvents.js`（新增） | 类型袋、地区袋、当前/预告资讯与轮数；提供只读资讯效果依据，依赖目录和随机工具。 |
| `src/opportunities.js`（新增） | 候选、阶段、个人额度及只读奖励/优惠条件；依赖目录和随机工具，不调用回合、经济或股票模块。 |
| `src/economy.js`（新增） | 原地产基础估值、租金与建造费用，以及优惠计划、现金/资金/额度提交；依赖棋盘、资讯与机遇计算，不反向调用股票模块。 |
| `src/stocks.js`（新增） | 股份、经营报价、分红、股票窗口、产权结算及清算经济；依赖基础经济、机遇条件，不调用编排、网络或记录生成。 |
| `src/assets.js`（新增） | 统一资产摘要；读取城市股份和待分红，依赖经济基础估值，不依赖原规则引擎。 |
| `src/gameView.js`（新增） | 按本人身份构建白名单投影、可操作报价及资产摘要；依赖目录、只读经济/股票接口与资产摘要。 |
| 原 `src/state.js` | 初始化规则版本、状态身份及新字段；原快照入口委托投影，不导入原规则引擎。 |
| 原 `src/gameLogic.js` | 保留回合和旧流程，作为跨组件协调入口；`settleGoEconomy` 的派息及起点奖励顺序也在这里编排，避免经济与股票互相调用。原基础经济导出委托经济组件。 |
| 原 `src/actionValidation.js` | 认证上下文、动作协议、版本、阶段与参数校验；引用规则的只读校验接口，不自行执行收付。 |
| 原 `src/actionClock.js` | 增加共享选择决定描述与三十秒时限；仍由房间管理暂停、恢复和可信超时。 |
| 原 `src/record.js` | 从结构化事件生成统计并使用统一资产摘要，移除对规则引擎的基础估值依赖；保留旧记录显示所需数据。 |
| 原 `server.js` | 房间身份、成功请求去重、候选状态提交、时钟、投影发布及记录保存；生命周期和终局调用同一经济结算入口。 |
| 原前端与 Service Worker | `public/client.js`、HTML、CSS、规则说明及缓存版本适配；已有视觉素材与三端棋盘继续使用。 |
| 现有测试目录 | 加入固定输入与假时钟夹具、规则/多人/浏览器场景；测试辅助不通过生产 Socket 增加调参或状态编辑接口。 |

依赖由上层到下层：房间 → 编排/校验/投影/记录 → 股票/资产/经济/轮次/资讯/机遇 → 固定目录/棋盘/随机工具。经济不调用股票，股票不调用编排，记录和资产不调用原规则引擎，因此没有相互导入循环。

### 自检与验证边界

- 八个新增模块分别服务于已经批准的职责；不加入通用插件系统、规则编辑器或额外玩法。
- 金额不会重复包含股息，建房成本与费用上限采用明确取整，提交前检查份额与资金守恒。
- 生产与测试使用同一规则路径，测试仅替换随机/时钟和构造输入，不新增远程作弊或调试操作。
- 首先检查已有未提交动作安全改动与原验证结果，完成本轮工作后按批准任务验证、提交相关变更。
- 最终检查包含 `npm test`、`npm run lint`、`npm run test:e2e`；具体场景及判据由 task.md 和 checklist.md 分别承接。
- 若记录落盘发生错误，记录该错误且保留已经提交的房间记录用于重试，不回滚已广播的账务，也不再次结算分红。仍沿用现有记录保存机制，不新增跨重启对局存档。
