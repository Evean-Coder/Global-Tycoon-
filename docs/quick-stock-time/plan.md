# 股票操作时限与列表稳定性 Plan

依据：spec.md。状态：2026-10-11用户统一批准开发；实现与实际验证见 acceptance.md。

## 代码核对

- `src/actionClock.js` 的 `decisionDescriptor` 当前把快速 `stock` 与一般决定同样设为20秒。
- `server.js/startTimer` 的 `quickStockBudget` 再将每个起点 `windowId` 的期限固定为20秒；转让后恢复时会受此预算截断。两处必须一致修订。
- `public/client.js/displayTimer` 驱动当前决定、初始选择及路线提示；股票弹窗目前没有相邻时间提示。沿用原事件和一个计时循环。
- 现有客户端成功下单后可能立即发送 `stock_done`，本轮保留该流程，不改成多批交互。
- `adjStock` 修改草稿后调用 `renderStock`；后者每次执行 `stockList.replaceChildren()`，重建全部卡片、数量按钮和details。普通/快速共用此路径，现有实现没有保留列表滚动参照、控件节点或展开状态。此为与跳动反馈相符的代码原因；实体手机复现仍待验收。

## 架构与数据接口

1. 个人时钟模块导出统一常量 `QUICK_STOCK_SECONDS = 60`。`decisionDescriptor` 对启用现有快速版本且处于 `stock` 的决定使用该值；转让确认仍20秒，其他分支原样。
2. 服务器股票窗口预算读取同一常量。新窗口生成 `elapsedDeadline = elapsedMs + min(QUICK_STOCK_SECONDS * 1000, totalRemainingMs)`；同 `gameId/windowId` 保留原截止。
3. `quickStockBudget` 数据形状保持 `gameId/windowId/elapsedDeadline/pausedAtElapsed`，不新增持久状态或Socket事件。不迁移已存在的预算；以后新打开的窗口按新值分配。项目服务重启仍按现状处理，不增加恢复存档承诺。
4. 股票弹窗添加 `#stockTimer` 文本节点；显示由 `displayTimer` 的同一服务端事件/快照及现有循环更新，不维护另一份期限或第二个定时器。暂停、0秒、终局及重新开局随原清理同步。打开弹窗时立即填入当前提示，不能等待下一秒或重新锚定计时。
5. 不改变 `stockContext`、请求回执、草稿、`windowId`、决定身份、额度及交易执行。接收方确认仍是其独立决定，不能误显示为发起方新的60秒股票时间。
6. 股票列表按 `data-stock-city` 对应的城市ID维护稳定卡片。分离卡片首次创建与同窗口更新；调整数量时沿用 `stockPreview` 重算全部城市额度，但只更新文字、数量、价格、原因与disabled属性，不清空列表或替换仍存在的按钮/details。事件委托继续调用原 `adjStock`；不重排城市。
7. 控件稳定标识采用城市ID、买卖类型、增减方向；城市名安全写入，不新增不安全HTML插入。报价依据details节点保留open属性，只更新内部解释。条件提示/帮助入口预留节点并更新内容及可见性，不能因加减数量替换卡片。
8. 实际滚动容器通过DOM和样式核对，覆盖 `#stockList`、弹窗自身及外层页面；避免只保存window.scrollY。局部修改前记录容器偏移、可见城市与相对位置，更新后仅在内容高度变化导致参照移动时同步补偿，并受真实滚动范围约束。不开延时滚动回调，不覆盖之后玩家手动滚动，不用每次scrollIntoView。
9. 同一窗口的资料导航保存浏览参照，返回时使用原身份校验恢复；只有新窗口允许首次初始化。焦点仍存在且启用时不搬移；若当前按钮因额度禁用，按需移到本卡片可用控件并使用 `focus({preventScroll:true})`。终局、换局和新窗口清理浏览参照，不改变原草稿生命周期。真实高度变化及列表底部的合法滚动范围变化不能当作跳顶；验收分别检查。

## 模块交互

新起点阶段→原引擎创建股票窗口→服务器按统一60秒分配窗口预算→个人时钟按窗口预算和整局余时取较小值→快照/原计时事件同步→股票弹窗显示同一剩余时间→确认或放弃走原动作。

进入转让编辑页仅改变客户端展示；发起真实转让才形成接收方20秒决定。返回股票阶段时，服务器用原窗口截止减实际已用时间，不能再给60秒。原窗口已耗尽时，恢复后由原个人超时路径提交 `stock_done`；不能提前替代接收方的合法决定。

认证重连→读取原快照/预算→显示剩余时间；按原离线策略暂停/恢复个人计时，并保留总预算收紧。总时限为0→现有快速封盘优先→旧请求和未成交事项沿原路径处理。

数量点击→原草稿变更及预览校验→在同一城市节点上更新数量，并更新全部城市相关额度、汇总和禁用原因→保持滚动及展开状态。收到同窗口快照同样走稳定更新；新窗口才清理旧浏览参照并初始化。确认交易仍沿原回执及结束路径，不把列表展示更新当成一次交易。

## 关键决策

- 选择60秒：股票需要比较多个城市及股数，普通模式已有60秒作为参照；仍可主动放弃或交易成功结束，不强制等待一分钟。
- 两处时间共用常量，避免个人时钟放宽而窗口预算仍20秒。
- 保留 `quick-mode-v1` 和现有协议：这是已批准后的时间配置修订，未改变请求格式或经济规则。新文档覆盖原快速规格F3/AC6中的股票时限，原历史验收仍保留当时结果。
- 更新玩家规则、静态资源查询版本及PWA缓存名；不强制刷新在玩的对局。服务端升级后旧缓存的规则文字可能暂时旧，不能因此覆盖服务端决定时间。
- 有限验证：固定时钟覆盖60秒边界、返回和总截止；真实Socket验证动作恢复及资金；浏览器验证弹窗相邻提示。不要用长时间真实等待代替可控时钟。
- 两种模式滚动验证使用固定长列表、真实按钮和实际滚动容器，在点击前后比较偏移与节点身份。不得用测试中先保存再恢复scrollTop掩盖产品跳动；兼测展开状态、限额禁用、异步报价和返回。移动端用触摸事件，PC补键盘检查。

## 自审

时间定义、窗口恢复、提示、规则和缓存分别承接F1–F6；稳定卡片、滚动/焦点参照与窗口清理承接F7–F8。服务器不依赖客户端时间；展示不反向延长预算；转让确认与股票原期限的关系已明确。上述为开发前核对；代码已实施，实际验证见 acceptance.md。
