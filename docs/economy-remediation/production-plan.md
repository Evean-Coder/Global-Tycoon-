## 2. 数据与接口

### 状态

- state.economyRevision：可选经济修订标识。
- state.travelExpenseReceipts：按玩家ID保存最近一笔{turnId,roundId,amount,settlementId}，最多4项，不追加无限数组。
- pending.resume：继续支持原布尔落点恢复；新增明确对象{kind:'travel_expense',continuation:'normal_end'|'skipped_jail'}，由服务端生成，不接受客户端自报。

### 模块接口

- stage(state)：completedRounds=roundFlow.index-1；返回{enabled,completedRounds,currentAmount,preview}。0–79为0，80–119为1500，120及以后为3000。
- preview：完整轮显示第79、80轮时预告第81轮1500；第119、120轮时预告第121轮3000。即completedRounds为78/79或118/119时出现；不用资讯独立计数。
- settle(state,playerId,events)：只给存活且标识有效玩家结算；同一turnId已结算直接返回已有结果。0费用阶段不发扣款事件。所有金额先核验再修改现金和凭据，生成结构化travel_expense事件。
- snapshot仅返回当前费用/预告/版本和本次费用所需公开信息，不投影内部恢复结构或身份令牌。

事件包含settlementId、playerId、turnId、roundId、completedRounds、amount、cashDeltas、fundDeltas={}以及可读文字。沿用既有settlementSeq生成凭据；费用不归其他玩家/城市基金，不受租金优惠抵扣。收费不是机遇，不消耗其额度。

## 3. 正常结束与跳过流程

### 正常回合

在advanceTurn的推进前调用settle：收费后现金非负，继续原推进；负数则停在当前回合，进入现有self_rescue并记录normal_end续接。当前回合未完成，不提前发布资讯、更新报价或换玩家。完成自救后回到advanceTurn；凭据命中，不再次扣钱。已经出局的当前玩家不收费，按原破产推进。

### 一回合监狱自动跳过

原prepareTurn循环直接切换玩家，绕过advanceTurn，必须另设结束跳过的共用辅助函数。先标记已消耗该次监禁，再结算费用：足额继续原跳过推进；负额进入原self_rescue，续接类型skipped_jail。自救完成后只完成这个跳过，不额外给一次掷骰。每人都跳过时按原顺序推进，轮次只完成一次。

极地/三回合监狱的主动合法跳过原本走正常结束，复用正常收费。入狱当次若结束了个人回合也计一次，下一次合法跳过是不同turnId。等待交易/拍卖/募资/股票期间不收费；它们最终完成个人回合时统一处理。

### 自救与出售

finishSelfRescue先识别travel_expense恢复对象；其他原resume逻辑保持。自救拍卖、直接出售、拒购/流拍、超时均通过原context保留resume对象。normalizeAction从真实pending补上下文，保持既有可信来源；客户端无需发送新字段。自救现金不足时按原破产及清算处理，最后存活者获胜。受费用影响的破产仍完成该玩家当前回合，不收下一次费用。

服务器继续预检→副本执行→经济不变量→提交→逐玩家快照；拒绝和重复actionId不提交费用副作用。断线只暂停时钟，不结算费用；重连显示同一收费凭据和债务。

## 4. 客户端、规则与记录

- 既有资讯栏增加远航开支当前额与提前2轮预告，暖白/海蓝原布局可换行；旧局明确适用旧规则。费用说明不用新增弹窗强制确认。
- 收费栏明确显示完整轮编号，以roundFlow投影为准，不能拿现有旧座位轮转计数解释收费阶段；预告说明距离下一档还有几个完整轮。
- 大厅规则说明第1–80轮0、第81–120轮1500、第121轮起3000；对局规则按当前修订展示。资产与现有自救弹窗使用真实扣款后状态。
- buildGameRecord保存economyRevision、最终阶段、总远航开支及逐玩家费用；回放按已记录事件展示，不按今天的规则重算旧记录。recordEconomySummary单列远航开支支出，不计成股息、净利润或机遇奖励。
- 静态资源标识与PWA缓存更新，避免旧客户端漏显示新费用。rules/readme/索引注明正式启用状态，与游戏代码一致。

### 有限正常开局对照

新种子2026100511/2026100512/2026100513，各运行原规则与费用候选两条，最多6条、250完整轮/6000动作；活动墙钟累计最多180秒，恢复不重置。分别固定2人投资/航空、3人地产/投资/航空、4人地产/投资/航空/谨慎。本人随机流固定，投资两侧共用已修正的独立策略，其余用旧冻结策略；单组只有远航费用规则不同。规则字段可不同，对比剔除这些声明后的初态核心；前80轮结束前核心流程应相同。

逐组报告胜者、轮数、投资出局次序、资产/现金/基金、实际费用和银行注入；费用导致投资更早出局时单列压力。三组中人数/对手不同，不合并成胜率，不宣布路线平衡；存在投资压力风险时先审查其原因与可见经营行为，再决定是否发布，不能把淘汰投资当平衡证明。

若候选未达门禁，保留代码与失败证据作为未启用修订，服务器新局仍沿用原经济规则，不冒称已解决长局。只有门禁通过后更新默认新局修订与玩家说明；已开始局不迁移。
