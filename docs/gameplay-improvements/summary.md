## 二、三类主动经营

### 2.1 共同行为

每个个人回合掷骰前，提供三个固定入口：**限时促销、股票投资、远程建设**。玩家选择一项成功执行，或直接跳过继续掷骰；不是随机抽到三张卡。原资产出售继续承担变现、自救用途。

查看说明、取消、非法操作及网络重试不应消耗经营次数；成功操作由服务端记账，同一回合不能重复执行。普通模式和快速模式都可使用，快速模式到时封盘优先于尚未完成的经营动作。

### 2.2 推荐候选数值

以下 P 为地价，标准建房费为 P×60%。

| 操作 | 支出与收益 | 时间定位 | 主要风险 |
|---|---|---|---|
| 限时促销 | 支出 min(P×4%,800)；每次合格收租获得银行奖励 min(P×8%,1200)，最多两次 | 短期现金收益 | 没人经过就损失活动费 |
| 股票投资 | 一笔买一座城市的1–2股；主动买入收1%手续费 | 中期经营收益与报价变化 | 城市经营不佳、清算或接近封盘可能亏损 |
| 远程建设 | 升一级，支付标准建房费的145%；优惠后最低135% | 长期租金增长 | 现金占用大，需要后续收租回本 |

#### A. 限时促销：为近期收租下注

- 仅本人非抵押城市可以启动，每玩家每个人圈最多一次。
- 活动在当前及下一完整轮有效，最多奖励两次；晚在本轮启动，实际有效时间较短，界面需显示剩余期限。
- 奖励只在其他玩家实际完成合格城市租金结算后支付；本人到访、报价预览或重复回执不触发。
- 银行支付额外奖励，租客原租金不增加；奖励不进入城市分红池或经营租金统计，避免同一奖金再次推高股票收益。
- 城市出售、抵押、失去产权，或本人出局、对局封盘后，停止后续奖励。没有保底收益或退款。
- 最高档支出800、最多奖励2400，净收益上限1600/个人圈。银行补贴对长期资金总量的影响还需检查。

该候选替代先前的“预支”思路：玩家承担促销成本，成功收租才获得奖励。

#### B. 股票投资：选择有经营预期的城市

- 沿用真实报价、市场余股、现金校验，以及总持股20股、城主本城最多4股等限制。
- 收益说明区分购入后新增分红、股价变化和已经包含在报价中的待分红，不把派息重复算成新增资产。
- 原起点交易窗口保留原规则；新增主动入口不能刷新起点额度。
- 每圈主动买入总额度、与起点额度如何共享，仍需正式规格确定，当前不将早期建议当作已批准规则。
- 原机遇对股票的影响保留；现有第三城持股奖励较强，需在组合场景中检查。

#### C. 远程建设：提前投入长期收益

- 本人非抵押城市一次升一级，城市最高4级；原落点建设继续采用原费用与优惠。
- 常规总费用为标准建房费×145%，不是地价×145%。
- 候选 H1 每圈一次减去标准费的10个百分点，即145%降到135%；其他优惠与其共用折扣上限，最低135%。只有实际产生优惠才消耗对应次数。
- 此 H1 调整属于新局候选规则，旧对局沿用原规则。
- 界面同时说明现金支出、租金增量与回本条件，避免把估值增长当成当场到账的现金。

### 2.3 已有模拟结论

比较135%、145%、155%三档建设费，每档867个指定局面、2508条轻量分支，共7524条分支，**没有运行完整对局**。

- 三档中，测试发现的无新增收租建设正收益场景由原24个降至0。
- 在27个经营差异场景中，145%档促销、股票、建设分别在4、15、8个场景中成为最高净资产选择。
- 这些次数是指定场景的比较结果，不是胜率。长期多次收租的基本场景仍主要有利于建设。

罗马地价12000、0级、无机遇和本人持股；股票目标为墨西哥城。促销费480、每次奖励960，买两股含手续费4606，远程建设10440。下表为相对“跳过”的新增净资产：

| 指定经营轨迹 | 促销 | 股票 | 建设 | 更合适 |
|---|---:|---:|---:|---|
| 1轮内本人城市与股票目标各收租一次 | +480 | +346 | +360 | 促销 |
| 3轮本人城市无人经过，股票目标收租三次 | −480 | +650 | −3240 | 股票 |
| 6轮本人城市收租六次，股票目标无人经过 | +1440 | −46 | +18360 | 建设 |
| 操作后立即封盘，没有新增租金 | −480 | −46 | −3240 | 跳过 |

因此推荐145%作为进一步设计的候选：三类操作有不同适用条件，玩家仍可选择保留现金。尚不能据此确认完整对局胜率平衡。

详细参数、脚本和证据见 [第二轮数值与复验](../active-management/numeric-balance-v2.md)。

### 2.4 正式规格需要解决的边界

股票每圈额度；监狱、冻结、自救和拍卖阶段是否开放主动经营；促销租金经过自救后何时计入；城市转移、断线及重复提交；经营操作与原倒计时的关系；临近封盘时的费用与失效提示。以上必须在实现前明确。

## 三、置业扶持

### 3.1 推荐首版：补充一次购地机会

候选规则：购地解锁后，玩家连续六个有效掷骰回合未获得城市、当前没有城市，并且此前未拥有过城市，可获得一次“置业扶持”。

| 项目 | 候选行为 |
|---|---|
| 可选地块 | 最多展示三座银行未售城市，优先低、中价位 |
| 购买价格 | 原地价，玩家自行支付 |
| 玩家选择 | 购买一座，或暂时不买 |
| 次数 | 每玩家整局最多成功使用一次 |
| 原购买限制 | 仍计入每个人圈最多购买四座城市 |
| 没有未售城市 | 保留资格，等待银行重新持有可售城市 |

目的在于让无地玩家获得一次经营入口。该方案不会夺取其他玩家城市，也不直接发现金。

### 3.2 防止刻意刷扶持

- 曾经拥有城市后主动出售，不能恢复新手扶持资格。
- 已遇到可负担的有效购地机会却主动放弃，不应继续累计“没有机会”；具体冻结或重置计数方式需确定。
- 监狱、冻结导致的跳过回合、飞行和重复处理不计入有效掷骰次数。
- 显示资格进度与未满足原因，避免玩家不知道为什么触发或没有触发。

六回合门槛、候选价格范围、现金不足后的资格保留、暂不购买后的再次展示时机，以及城市被他人先买走的处理，目前仍是待确定参数。置业扶持尚未进行模拟，不应声称已经平衡。

### 3.3 可选第二阶段：连续付租缓冲

如果购地机会仍不能改善前期体验，可另行评估：购地解锁后，无城市玩家连续三个有效掷骰回合实际支付城市租金，下一次城市租金减免20%、最高1500，整局一次。

银行补足城主及分红应收，避免转嫁损失。与现有减租机遇的叠加顺序和总上限需明确。建议先验证置业扶持，再决定是否增加该缓冲，防止补偿过量。

## 四、游玩规则提示

### 4.1 优先完善城主持股上限

当前规则速查和部分限制原因已经写有“本人城市最多持有4股”，服务端买入及转让也有校验。问题是股票列表没有持续明确显示“城主身份”和“4股上限”，玩家容易与每窗口单城买入2股混淆。

建议股票购买与转让界面显示：

| 场景 | 展示示例 |
|---|---|
| 本人城市，持有3股 | **你的城市 · 已持有3/4股**；本次最多可买1股 |
| 本人城市，持有4股 | **已达城主持股上限**；不可继续买入，仍可卖出 |
| 本窗口已经买过该城 | 本窗口单城剩余额度，与持股上限分别显示 |
| 接收本城股票转让 | 接收后持股不能超过4股；超限时显示具体原因 |

实际可买数量同时受持股上限、窗口额度、市场余股、总持股及现金限制，展示结果应与服务端一致。不能用一个“购买失败”覆盖所有原因。

### 4.2 其他高频规则提示

| 操作位置 | 需要说清楚的规则 |
|---|---|
| 买地 | 首圈购地解锁条件、个人圈购买数量限制、现金不足原因 |
| 股票 | 单窗口最多三城、六股、单城两股；本人总持股20股与本城4股是持有上限 |
| 股票经营说明 | 分红来源、经营报价变化、清算风险；派息不重复计入收益 |
| 机场 | 免费飞行看出发机场是否属于本人；已付通行费与飞行费用分别列出 |
| 资产与银行 | 现金、资产估值、净资产的区别；抵押本金与利息影响结算 |
| 快速模式 | 总时限与本次操作倒计时分别显示；到时封盘及排名依据明确 |
| 未来主动经营 | 一回合一次、费用计算基数、促销期限与次数、建设现金占用 |
| 未来置业扶持 | 触发进度、一次性限制、原价购买和资格保留原因 |

规则提示放在相关按钮、报价和数量旁边。禁用按钮仍应让触屏、鼠标和键盘用户看到原因；完整规则保留在速查中。查看帮助不消耗机会，也不延长倒计时。涉及旧局或不同规则版本时，展示该局实际规则。

## 五、整套前端改版

### 5.1 已确认的最终方向

采用《文明6》风格的原创历史地图与策略界面。此前的海景远征、莫兰迪、玻璃蓝白方案已被用户推翻，不作为本轮实现依据。

- **背景与材质：** 羊皮纸世界地图，浅色顶栏、菜单和操作区，黄铜细线与实体纸质面板；不使用深蓝大面积界面或简单透明叠层。
- **字体：** 现代黑体搭配清晰的系统无衬线字体，金额采用等宽数字排布；不沿用此前宋体标题方案。
- **中央地图：** 专门制作一张完整缩小版世界地图，铺满棋盘内部矩形区域，不复用外围地图素材；海洋色与外围灰蓝海洋一致。正式实现需保持大陆完整与合理比例，不能照搬demo的图片拉伸方式。
- **悬浮模块：** 仅整合用户截图区域中的本人资产、现金、城市/机场、环球资讯与当前回合提示，形成一个模块悬浮于中央地图。保留原资产台账和资讯入口，不扩展为其他新玩法。
- **模式选择：** 普通、快速模式用两张选择卡，展示时长、获胜条件和选中标记，支持触控与键盘；遵守原房主权限和服务端状态。

### 5.2 全界面与三端要求

统一大厅、房间、正式对局，以及资产、股票、转让、银行、机遇、资讯、购地、建设、机场、监狱、冻结、自救、拍卖、规则、连接提示和结算。demo未完整模拟的正式状态也必须采用同一套组件样式。

PC以棋盘和经营信息为主，平板横竖屏分别重排。手机直接保留42格名称、金额、归属、建设和抵押信息，开局前及对局竖屏提示横屏；短横屏可正常纵向滚动，不能隐藏地图文字或由操作栏遮挡地块。正式适配不照搬demo中竖屏地图横向滚动的临时方式。

改版保留服务端规则、Socket动作含义、按钮操作顺序、交易草稿、报价确认、转让返回、连接提示及倒计时。示例金额、人物、机遇占位说明和设计预览菜单不进入产品。

## 六、建议实施顺序与有限验证

建议将玩法、提示和前端拆为独立子项目，分别完善规格：

1. **游玩规则提示**：先补充现有约束的可见性，减少误操作和误报故障。
2. **置业扶持**：明确六回合计数、拒绝机会和候选城市规则，再用指定场景验证。
3. **三类主动经营**：冻结每圈额度与优惠边界，验证组合收益后开发。
4. **整套前端改版**：按本轮已确认视觉完成正式文档审批与三端验证；与规则提示共用展示组件，避免重复修改。不将视觉改版与新玩法强制绑为一次发布。

该顺序是建议，不改变已经批准的其他开发任务。进入实现时按 ic-spec 分别形成并审批四份文档。

验证以有限指定场景为主：

- 提示：本城持股0、2、3、4股；窗口额度耗尽、库存不足、现金不足和接收转让；手机、平板、PC均能看到原因。
- 扶持：连续六次无机会、主动拒绝购买、买地后出售、跳过回合、没有库存、候选被抢先购买、重连及重复提交。
- 经营：短中长期收益对照、无租金、最大优惠、持股奖励组合、低现金、自救后付款、城市转移、促销到期和快速封盘。
- 流程：少量多人联机场景检查操作次数、倒计时及状态一致性，不启动上千次完整对局。
- 前端：指定PC、平板横竖屏、手机横竖屏及320px宽度，检查地图加载、文字、悬浮模块、模式卡、焦点、缩放、缓存更新和相关现有交互回归。

本次只汇总方案，没有修改正式游戏规则、实现代码或部署版本。
