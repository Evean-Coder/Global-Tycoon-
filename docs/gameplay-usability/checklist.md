## 验收方式与范围

每项通过实际运行或观察验证，不能用实现完成、文字修改或早期正常路径通过代替验收。相关条目可以共用一次受控场景，但分别记录结果。只有验证通过才勾选，失败记录预期、实际、修复及相关重跑证据。

使用task.md固定的定向命令与测试文件；浏览器每项60秒超时，股票异常最多8组。地图矩阵固定为320×568、375×812、430×932及其横屏、768×1024、1024×768和1440×900，另做真实200%缩放与缓存更新。受控状态准备与实际Socket动作分开记录，不模拟完整对局、不重新检验胜率。

## 股票窗口与交易

- [x] **C08：下一圈再次购买。** 第一窗口买3城各2股后结束，第二次实际经过起点建立新窗口，累计已买归零、可买额度恢复，再买同3城各2股成功。（验证：其他玩家城市、充足现金/供给，真实掷骰与下单，核对窗口、每城持股和两批扣款；AC5。）
- [x] **C09：旧草稿清理。** 上一窗口报价失败、未提交和超时关闭三种草稿都不带到新窗口，旧报价及错误也不残留。（验证：分别准备旧草稿并关闭/切换，观察新数量、依据和错误；AC6。）
- [x] **C10：迟到回执隔离。** 旧成功/失败回执不清空新草稿、不关闭新弹窗、不提交新动作，旧请求也不能解除新请求的锁。（验证：测试端延迟投递实际回执，记录新窗口内容、按钮状态与发送动作；AC6。）
- [x] **C11：转让返回保留额度。** 同一窗口转让成功、拒绝或界面返回后，累计买入不重置，按实际持股重算当前订单资格。（验证：真实发起与接收方确认/拒绝，比较返回前后累计及持股；AC7。）
- [x] **C12：重连与新对局隔离。** 同窗口断线重连不重置累计买入；刷新页面可用空草稿恢复真实额度；新对局不继承旧数量或异步副作用。（验证：使用原认证重连及重新开局，观察窗口身份、额度与草稿；AC6、AC7。）
- [x] **C13：窗口限制提示。** 单城2股、总6股、3城上限分别显示累计和剩余，草稿占用城市按并集计算；卖出不恢复已经使用的买入额度。（验证：分别达到限制，再减量/卖出，核对按钮原因及服务端校验；AC8。）
- [x] **C14：持股与供给限制。** 本人城市持有4股停止买入，全城20股售尽显示供给不足；其他玩家城市持有4股后仍可在额度/供给允许时买入。（验证：三个独立受控状态，观察就地原因并执行合法/非法订单；AC8。）
- [x] **C15：买卖金额与现金。** 现金不足有明确原因；卖城市A取得的收入可以支持同批买城市B，卖出按实际持股，不引入当前规则禁止的同城买卖。（验证：核对买入额、卖出额、净变化与实际现金/持股，对照整批服务端结果；AC8、AC9。）
- [x] **C16：新报价明确确认。** 报价版本或重新经营批次变化后保留数量、展示旧/新依据；更新报价不成交，玩家再次确认才发送交易。（验证：使原订单依据失效，记录两次点击间动作数及最终价格；AC10。）
- [x] **C17：失效订单原子拒绝。** 报价、持股、额度、现金变化导致拒绝时，订单没有部分成交；现金、持股、累计额度与决定截止时刻未被拒绝动作修改。（验证：提交前后快照/时钟比较，核对明确失败反馈；AC10。）
- [x] **C18：无确认与原身份重试。** 未收到结果不显示成功，不自动生成新订单；原请求重试保持同一身份及载荷，最多一次自动重试，最终至多成交/扣款一次。（验证：测试端注入无确认及实际重复请求，核对载荷、回执、持股和现金；AC11。）
- [x] **C19：同步后结束原窗口。** 回执先于状态呈现或动画未完成时，等待有效状态再结束；已换窗/超时则不补发。正常成功仍自动继续原回合。（验证：注入呈现延迟及窗口切换，检查后续动作身份、状态版本和回合；AC6、AC11。）
- [x] **C20：结束失败不重复买卖。** 买卖已经成功、结束窗口失败时，提示已成交而窗口未结束；重试只结束窗口，不重新执行订单。（验证：独立拒绝结束动作后恢复，统计交易、扣款及结束动作；AC11。）
- [x] **C21：历史交易兼容。** 旧v1正常交易保持原规则，缺现代字段不报错，未确认股票订单不自动补发；未启用远航修订的旧v2仍使用真实现代窗口额度。（验证：历史状态定向回归及浏览器受控场景，不迁移旧局规则；AC7、AC17。）
